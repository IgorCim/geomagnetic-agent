# Руководство по геомагнитному агенту

## Задачи исследователя

Это исследовательский прототип ассистента для геомагнитных временных рядов. Пользователь задаёт по-русски станцию, период и нужный результат; локальная языковая модель выбирает зарегистрированные операции. Python загружает данные, рассчитывает производные, строит интерактивные графики и собирает проект. При отсутствии данных или отказе поставщика система должна сообщать причину, сохраняя доступные результаты.

Практическая ценность — сократить ручную последовательность «найти данные → привести формат/время → вычислить → построить → подписать → разложить файлы → упаковать». MVP позволяет исследовать дни и станции в чате и повторять пакетные задания. Он не заменяет квалифицированную научную интерпретацию, официальные индексы и системы оперативного предупреждения.

Название SaaS описывает направление развития. Текущая поставка — Python-приложение с Gradio и локальными файлами; эксплуатационная платформа с организациями, платежами и изолированными заданиями ещё не построена.

## Архитектура

Модель — Qwen 2.5 14B Instruct GGUF Q4_K_M через llama-cpp-python. При явном запуске загружаются веса, модель остаётся в процессе. Коммерческий LLM API не используется. Для загрузки внешних геофизических данных по-прежнему нужен интернет; модель выполняет расчёт локально.

Обычный запрос идёт через `run_agent`. Маршрутизатор выбирает схемы инструментов для запроса. Ответ модели разбирается из структурированных вызовов, тегов `<tool_call>` или поддерживаемых JSON-форм. Диспетчер разрешает только известные инструменты из предложенного набора. Результат инструмента возвращается модели в сокращённом виде; полный DataFrame остаётся в Python.

FrameStore адресует таблицы строковыми идентификаторами, например `raw:irt:2024-09-10`, `derived:irt:2024-09-10`, `sw:omni:2024-09-10`. Регистр идентификаторов нормализуется. Семейство `raw` — псевдоним последней таблицы, а не способ обозначить сразу несколько дней. Это предотвращает перезапись одного дня другим при сравнении.

Scratchpad хранит краткую рабочую память текущего запроса и подсказки коррекции. По умолчанию обычный цикл ограничен 28 вызовами инструментов и 25 раундами модели. Для заданий планировщика действуют отдельные ограничения; один вызов матричного инструмента может выполнить много Python-операций. Поэтому ограничение числа вызовов инструментов нельзя выдавать за общий лимит всех сетевых запросов или времени задачи.

## Два режима исполнения

В коротком диалоге модель последовательно выбирает инструменты. В больших заданиях LLMPlanner формирует структурированный план; конкретные задачи с полными аргументами исполняются напрямую. Большие однородные планы могут сворачиваться в матрицу «станция × дата». При `run_until_complete=True` исполнитель проходит станции и события, отмечает успешные/провалившиеся ячейки и вызывает экспорт.

Это осознанная граница ответственности: модель планирует, Python исполняет массовую работу. Успешный такой прогон доказывает работу планирования и исполнителя в заданных условиях, но не доказывает способность модели автономно удерживать сотни отдельных вызовов инструментов в одном контексте.

## Данные, графики и происхождение результата

Основные ряды обсерваторий: X/Y/Z/F. H/D/I вычисляются через hypot/atan2; D/I выражены в градусах. Статистика включает минимум, максимум, размах, среднее, медиану и стандартное отклонение и описание пропусков. Аномалии определяются относительно среднего и стандартного отклонения выбранного ряда; это статистическая процедура.

Графики Plotly сохраняются в HTML и отображаются через фиксированные gr.Plot. Для смешанных единиц используются отдельные панели. В длительных рядах для отображения может отбираться каждый n-й отсчёт; график не следует считать точной визуализацией каждого экстремума полного набора без проверки исходных данных. NaN не соединяются через connectgaps.

Проект использует дерево `<project>/<station>/<date>/`, CSV и манифест, индекс charts.json и обозначения источника в именах файлов. В charts.json фиксируются данные графика, идентификаторы использованных таблиц и хеш файла. Экспорт добавляет CSV/HTML-индекс и export_manifest. Заданная пользователем структура ZIP не должен переименовывать канонические графики проекта. Повторный экспорт обновляет некоторые метаданные; утверждение «вообще ни один байт проекта не меняется» было бы слишком сильным.

В Gradio одновременно показывается до 12 превью; после текущих исправлений список скачивания сохраняет все графики чата. Частичный отказ не должен прятать уже созданные файлы. Результаты матриц берутся из успешных ячеек внутри разрешённого проекта.


## Работа исследователя в Gradio

В одном чате можно менять компоненту, станцию и дату. Точные идентификаторы таблиц видны в ответе. Запрет повторной загрузки вместе с отсутствующим идентификатором таблицы должен дать unknown_frame. На двух устройствах проверена изоляция таблиц сессии. Проекты на диске и ссылки на экспорт требуют отдельной модели доступа при публичном развёртывании.

У plot_components режим stacked размещает компоненты вертикально, overlay накладывает их в одной панели. Три самостоятельных HTML получаются отдельными вызовами по одной компоненте. Для нескольких станций используется plot_overlay с системой UT, LT или MLT. Визуальное смещение кривой сохраняет значения исходного ряда.

Пользователь задаёт структуру выпуска, модель передаёт пути в folders. Python проверяет принадлежность файлов проекту и формирует окончательные имена HTML. Поддерживаемые вызовы могут передать предпочтительное имя. В проекте сохраняется каноническое дерево станция/дата. В ZIP можно положить рядом файл и подпапку, объединить разные даты и станции, использовать кириллицу и пробелы. Режим direct кладёт файлы непосредственно в указанные папки, tree сохраняет пути, auto различает точный файл и выбранное дерево. Конфликты одинаковых имён разрешаются кодом. Фактическое соответствие проверяется по export_manifest.json и содержимому архива.

## Шесть поставщиков и пределы покрытия

## INTERMAGNET

Код: `intermagnet_loader.py`.

Реализованы GetCapabilities, объединение каталогов Edinburgh/Kyoto, GetData с ориентацией XYZF, JSON/IAGA-2002, даты и состояния публикации, запросы блоками по 31 дню, повторные попытки, сортировка, удаление дубликатов времени, кэш Parquet и запись CSV при отсутствии pyarrow. При отсутствии запрошенного состояния загрузчик пробует резервный вариант. Поэтому запрос definitive не гарантирует, что фактически получен definitive.

Не реализованы все GIN-операции: каталоги доступности по датам, времена модификации, анализ задержек сети и прочие административные/статистические службы. Нет автоматического подтверждения полноты каждого дня по всем ожидаемым минутам. В кэше известны ограничения восстановления метаданных и чтения резервных файлов CSV; см. разбор кода. Секундный режим присутствует во входном контракте, но все вычисления нельзя автоматически считать корректными для секундного ряда.

Публичный каталог в проверке 01.11.2026: HTTP 200. Это не тест каждой пары «обсерватория — дата».

Первичные источники: [Загрузка данных INTERMAGNET](https://intermagnet.org/data_download), [полный перечень служб GIN](https://imag-data.bgs.ac.uk/GIN_V1/).

## NASA CDAWeb / OMNI

Код: `space_weather_loader.py`, `fetch_solar_wind`.

Поддержаны `OMNI_HRO2_1MIN` и резервный `OMNI_HRO_1MIN`. Метаданные HAPI определяют имена столбцов и коды пропусков. Выход: timestamp, V, Np, T, Bx, By, Bz. By/Bz — GSM; Bx исходно BX_GSE. Пропуски превращаются в NaN. `align_solar_wind` совмещает ряд с временной осью станции и допускает ограниченную интерполяцию.

Не реализованы остальные миссии и наборы CDAWeb, произвольный выбор параметров, универсальный HAPI-клиент, живые ACE/DSCOVR-потоки, автоматическое установление причинности или прогноза. Резервирование набора не является гарантией заполнения дыр во всех полях.

Научно важная деталь: ряд OMNI высокого разрешения уже перенесён к носовой части земной ударной волны; время соответствует прибытию. Называть его просто «сырыми измерениями L1» или повторно добавлять фиксированную задержку без обоснования нельзя. Сдвиг по умолчанию (`lag=0`) соответствует отсутствию дополнительного ручного сдвига.

Проверка метаданных: HTTP 200. Первичные источники: [Метаданные OMNI в HAPI](https://cdaweb.gsfc.nasa.gov/hapi/info?id=OMNI_HRO2_1MIN), [описание временной привязки NASA](https://omniweb.gsfc.nasa.gov/html/HROdocum.html).

## WDC Kyoto

Код: `space_weather_loader.py`, `fetch_geomagnetic_indices`; также резерв станционных данных в загрузчике INTERMAGNET.

Поддержаны `hour_dst` и `hour3h_kp`. Dst и Kp совмещаются по часам; одно трёхчасовое значение Kp распространяется на три часа. Это удобство сопоставления, а не три независимых измерения и не переход к часовому разрешению Kp.

Не реализованы остальные индексы каталога — AE/AL/AU, ASY/SYM, ap/Ap и другие продукты, произвольный выбор набора данных, выбор фиксированной версии и сохранение всех полей качества/версии. Публичный каталог сейчас отвечает HTTP 200.

Источник: [официальный HAPI Kyoto с каталогом и форматами](https://wdc.kugi.kyoto-u.ac.jp/hapi/). Kp в этом сервере атрибутируется GFZ, а не объявляется собственным индексом Kyoto.

## NOAA SWPC

Код: `noaa_swpc_loader.py`.

Поддержаны три операции: фильтрация геомагнитных уведомлений и предупреждений, текущий прогноз Kp и каталог рентгеновских вспышек по данным GOES за последние семь дней. Преобразуются времена и шкалы G1–G5; у прогноза выделяется максимум. Название `fetch_solar_wind_forecast` историческое: функция получает прогноз **Kp**, а не скорость, плотность и IMF солнечного ветра.

Не реализованы все продукты SWPC: исторический поиск вспышек за произвольный год, все R/S/G-уведомления, полный набор GOES, модели, карты и продукты спутников. Вопрос о мае 2024 к семидневному каталогу не даёт исторической справки: пустая выборка не означает отсутствия вспышек в мае 2024.

В проверке 01.11.2026 службы уведомлений и прогнозов: HTTP 200. Проверка адреса не подтверждает каждое преобразованное поле. Источник: [официальный каталог JSON-продуктов NOAA](https://services.swpc.noaa.gov/products/).

## SuperMAG

Код: `supermag_loader.py`.

Реализован клиент трёх старых путей: `data-api.php`, `indices.php`, `inventory.php`. Станционные данные — возмущённые dX/dY/dZ и географические компоненты с уже удалённой базовой линией; это не абсолютные X/Y/Z INTERMAGNET. Индексы ограничены SME/SML/SMU. На один запрос станционных данных в текущем коде установлен предел **24 дня**. В старых описаниях встречается 32 — это устаревшее число.

Логин хранится на FrameStore браузерной сессии и передаётся загрузчику. При запуске из командной строки логин также можно передать через переменную окружения `SUPERMAG_LOGON`. В новой диагностике параметр logon в URL маскируется; поле пароля и секреты не должны попадать в видео.

01.11.2026 выполнен публичный запрос к `https://supermag.jhuapl.edu/services/indices.php?python&nohead`: HTTP **404**. Текущий клиент этот адрес использует. Это свидетельство отказа по старому адресу, не доказательство закрытия всего SuperMAG. Авторизованная загрузка и новый API в этом прогоне не проверены. Переход на другую службу без анализа формата/правил не выполнен.

Исторически в ACCEPTANCE.md зафиксированы два успешных 15-дневных окна по 21 600 строк. Это прошлое состояние интеграции; сохранённый вывод блокнота Kaggle и его ограничения разобраны в [docs/evidence/README.md](evidence/README.md). Это копия вывода блокнота без отдельной записи исходного потока вывода; для полного подтверждения всё ещё нужны исходный лог и артефакты. Источник общей интеграции: [SuperMAG](https://supermag.jhuapl.edu/); исторический 404 подтверждён сохранённым локальным HTTP-отчётом, а не догадкой о логине.

В Colab на 9a9e211 авторизованный запрос фактически вернул 1440 строк SME/SML/SMU за 10 сентября 2024. В интерфейсе логин вводится отдельно от текста запроса. Секрет получает Python-загрузчик, схема инструмента для модели его не требует.

## NASA ISWA

Код: `iswa_loader.py`.

Выбраны HAPI-наборы `NOAA_KP_P3H` и `dst_quicklook`. Окно формируется относительно текущего UTC: назад 24 часа, вперёд 48, вывод с шагом три часа. Для Kp различаются наблюдаемые, прогнозные, оценочные и опубликованные значения. Оперативный Dst характеризует наблюдаемое состояние; прогноз будущего Dst здесь отсутствует. Недоступность Dst не обязана обрушить доступный Kp.

Ветка `get_ground_perturbation_map` по умолчанию возвращает `service_decommissioned` **до сетевого запроса**. Сохранившийся WMS-клиент и синтетический PNG нужны для тестов/совместимости. Значит, ответ этого инструмента подтверждает политику текущего кода, но сам по себе не доказывает официальную декомиссию продукта NASA. В документации следует говорить «карта из прежней версии сервиса не поддерживается текущей интеграцией».

Не реализованы весь каталог HAPI, cygnets, поиск файлов, дерево данных, выбор источника по произвольному идентификатору dataID и новые файловые API ISWA. Официальная NASA-страница описывает обновление приложения и дополнительные API; это отдельный объём работ. В проверке 01.11.2026 каталог HAPI: HTTP 200, а не проверка успешности обоих выбранных запросов данных.

Источник: [NASA CCMC: ISWA и её веб-службы](https://ccmc.gsfc.nasa.gov/tools/ISWA/), [Каталог HAPI](https://iswa.ccmc.gsfc.nasa.gov/hapi/catalog).


Старый WMS находился на iswa.gsfc.nasa.gov/wmts/wmts.cgi. Новый портал расположен на iswa.ccmc.gsfc.nasa.gov. При проверке проекта эквивалентный публичный слой карты там не найден. Ожидаемый ответ клиента service_decommissioned позволяет явно сообщить об отсутствии изображения. HAPI-прогноз работает отдельным маршрутом.

## Контракты всех 29 инструментов

В справочнике приведены параметры из `TOOL_SCHEMAS`. Инструмент `get_statistics` входит в общее число.

### `fetch_observatory_data`

Загружает данные одной обсерватории INTERMAGNET за указанный период. Возвращает идентификатор вида `raw:irt:2024-09-10` для последующих операций.

- `station_code` (строка, требуется). Трёхбуквенный код станции IAGA, например IRT (Иркутск).
- `start_date` (строка, требуется). Начальная дата в UTC, формат YYYY-MM-DD.
- `end_date` (строка, требуется). Конечная дата в UTC, включительно, формат YYYY-MM-DD.
- `data_type` (строка). Статус публикации. По умолчанию `definitive`. Режим `auto` последовательно проверяет доступные статусы. Допустимые значения — `definitive`, `quasi-def`, `adjusted`, `reported`, `best-avail`, `auto`.
- `samples_per_day` (строка). Временное разрешение. По умолчанию минутные данные (`Minute`). Допустимые значения — `Minute`, `Second`.

### `create_project`

### `create_task_matrix`

Создаёт матрицу по станциям и датам для большой серии однотипных операций. Каждая задача станции объединяет даты её событий. Для обработки созданной матрицы вызывают `process_matrix_batch`.

- `events` (массив, требуется). Даты событий в формате YYYY-MM-DD.
- `stations` (массив, требуется). Список трёхбуквенных кодов станций IAGA.
- `actions` (массив, требуется). Операции для каждой пары станция–дата в порядке исполнения. Стандартная последовательность — fetch, calc_HDI, plot. Допускаются полные имена обработчиков.
- `project_name` (строка, требуется). Проект для матрицы и её результатов.
- `shared_args` (объект). Общие параметры ячеек. Для сравнения с солнечным ветром требуется solar_wind_df_descriptor. По умолчанию сравниваются H и параметры Bz, V. Матрица подставляет наземную таблицу и имя файла для каждой ячейки.
- `export_args` (объект). Параметры автоматического экспорта, например archive_name, folders, sort_by, source_order и include_index.

### `process_matrix_batch`

Обрабатывает ожидающие станции из сохранённой матрицы. При полном проходе автоматически собирает архив и возвращает сводку покрытия.

- `matrix_path` (строка, требуется). Путь, возвращённый create_task_matrix.
- `run_until_complete` (логическое значение). При true обрабатываются все оставшиеся станции, при false — одна партия.
- `batch_size` (целое число). Число станций в партии при run_until_complete=false. По умолчанию 5.
- `export_args` (объект). Переопределяет параметры экспорта, сохранённые в матрице.

### `calculate_derived_math`

Вычисляет размах, скорость изменения или отклонение от опорного уровня. Возвращает идентификатор таблицы результата и численную сводку.

### `evaluate_custom_formula`

### `plot_components`

- `bbox` (массив). Границы изображения [запад, юг, восток, север] в градусах. По умолчанию весь мир.
- `width` (целое число). Ширина изображения в пикселях. По умолчанию 1024.
- `height` (целое число). Высота изображения в пикселях. По умолчанию 512.

### `get_iswa_forecast`

Возвращает Kp на трёхчасовой сетке и оперативные наблюдения Dst. Поле `kp_kind` различает наблюдение, оценку и прогноз. Вызывается без аргументов.


## Вычисления и единицы

H = hypot(X,Y) в нТ, D = degrees(atan2(Y,X)), I = degrees(atan2(Z,H)). Модуль вектора из XYZ равен sqrt(X²+Y²+Z²). Статистика учитывает конечные значения и пропуски отдельно. Среднее H за ночное окно calculate_baseline и медианная опора sq_baseline могут различаться. Аномалия H минус базовое значение и выброс за sigma_threshold отвечают на разные вопросы.

Язык пользовательских формул поддерживает +, −, *, /, %, **, унарные знаки, скобки, pi, e и функции abs, acos, asin, atan, atan2, cos, degrees, exp, hypot, log, log10, maximum, minimum, power, radians, sign, sin, sqrt и tan. Результат сохраняется в колонке FORMULA. Доступ к атрибутам, произвольные функции и индексирование отклоняются. Отсутствие конечных значений даёт вычислительную ошибку. [Примеры всех режимов](qa/FORMULA_RUNBOOK.md).

## Физические метрики

Контракты функций из physics_engine.py приводят определения, единицы и допущения для интерпретации.

### `extract_sq_baseline`

Определяет фоновое поле по ночному окну. По умолчанию берёт медиану каждой из компонент X, Y и Z между 00:00 и 04:00 UT. Медиана мало чувствительна к единичным выбросам. Параметр `method` принимает значения `night_median` и `night_mean`. Окно `night_hours` может пересекать полночь.

Функция возвращает копию таблицы с постоянными столбцами `X_sq`, `Y_sq`, `Z_sq`, `H_sq` и `F_sq`. Горизонтальную составляющую вычисляет как `hypot(X_sq, Y_sq)`, полный модуль — как `hypot(H_sq, Z_sq)`. Если время определить невозможно или в окне нет отсчётов, функция возвращает ошибку.

### `calculate_deltas`

Вычитает фон Sq из каждой компоненты и записывает разности в `dX`, `dY` и `dZ`. Затем вычисляет горизонтальный модуль отклонения `dH = hypot(dX, dY)` и полный модуль `F_delta = hypot(dH, dZ)`. Оба модуля выражены в нТ. Если передана исходная таблица без фоновых столбцов, функция сначала вызывает `extract_sq_baseline`.

### `calculate_gic_proxy`

Вычисляет скорость изменения горизонтального поля. Для минутных средних INTERMAGNET разность между соседними отсчётами H даёт `dH_dt` в нТ/мин. У первого отсчёта нет предыдущего значения, поэтому результат равен `NaN`. Максимум абсолютной скорости сохраняется в `attrs['dH_dt_peak_abs_nT_per_min']`. Это косвенный показатель условий возникновения геомагнитно-индуцированных токов. Для оценки самого тока в амперах потребовалась бы модель проводимости и электросети.

### `calculate_dst_proxy`

Оценивает возмущение по горизонтальному полю одной станции. Функция вычитает фон `dH = H - H_sq` и применяет широтный множитель `dst_proxy = dH * cos(latitude)`. Если в таблице отсутствует `H_sq`, функция предварительно вычисляет фон по ночному окну.

Падению H относительно фона соответствует отрицательное значение. Величина в нТ зависит от опорного уровня и широты станции. Для сравнения с официальным Dst следует использовать наблюдения Kyoto.

### `calculate_coupling_function`

Вычисляет электрическое поле по принятой в OMNI формуле `Ey = -V * Bz * 0.001`. Скорость V задаётся в км/с, компонента Bz в системе GSM — в нТ, результат — в мВ/м. При V = 400 км/с и Bz = −5 нТ получается +2 мВ/м. [Описание параметра 29 в OMNI](https://omniweb.gsfc.nasa.gov/html/ow_min_data.html).

Через `solar_wind` передают таблицу солнечного ветра, согласованную по времени с наблюдениями станции. Имена столбцов распознаются без учёта регистра. Для скорости допустимы `V`, `V_sw`, `speed`, для поля — `Bz`, `Bz_gsm`, `B_z`. Если передана одна строка, её значения применяются ко всем строкам станции. При отсутствии данных солнечного ветра функция возвращает `missing_solar_wind`.

### `detect_ssc`

Ищет кандидатов на внезапный импульс по быстрому росту H. Скорость нормируется на фактический интервал между временными метками. Порог `threshold_nT_per_min` по умолчанию равен 5 нТ/мин. Близкие превышения объединяются с учётом `SSC_MIN_SEPARATION_MIN`. Из каждой группы выбирается отсчёт с самым быстрым ростом.

В таблицу добавляются `ssc_flag` и `dH_dt`. Полное число обнаруженных событий хранится в `attrs['ssc_count']`, первые десять — в `attrs['ssc_events']`. Если событий больше, устанавливается `attrs['ssc_events_truncated']`. Для события сохраняются пиковая скорость `dH_dt_nT_per_min` и амплитуда ступени `step_nT` — разность средних H за пять минут после и до начала. Это помогает отличить устойчивую ступень от одиночного выброса. Для подтверждения SSC нужны независимые данные об ударной волне солнечного ветра или согласованные наблюдения нескольких станций.

### `calculate_burton_coupling`

В модели Бёртона южная компонента межпланетного магнитного поля усиливает кольцевой ток, а его затухание возвращает отрицательный Dst к нулю. Реализация использует уравнение `dDst/dt = -a * sqrt(Np) * V * Bs - Dst / tau`, где `Bs = max(-Bz, 0)`, `a = 0.005`, а `tau` равно 8 часам.

Из таблицы `solar_wind` берутся концентрация Np (см⁻³), скорость V (км/с) и Bz (нТ). Начальное значение Dst берётся из необязательной таблицы `indices`. Если её нет, расчёт начинается с Dst = 0 нТ. Функция записывает величину инжекции в столбец `burton_coupling` (нТ/ч) и делает один шаг Эйлера на час вперёд. В `attrs['burton']` сохраняется результат этого шага. Его применимость ограничена заданными начальными условиями.

### `calculate_akasofu_epsilon`

Оценивает мощность передачи энергии солнечного ветра в магнитосферу по параметру ε Акасофу. Используется выражение `ε = V * B_total² * l0² * sin⁴(θ/2) / μ0`. Здесь `B_total = sqrt(Bx² + By² + Bz²)`, θ — угол поля в плоскости By–Bz с учётом квадранта, а `l0` равно семи радиусам Земли. Для чисто северного поля угловой множитель равен нулю, для чисто южного достигает максимума.

На входе `solar_wind` содержит V в км/с и компоненты B в нТ. При вычислении величины переводятся в СИ. Результат в ваттах записывается в столбец `akasofu_epsilon`, значения в ваттах и эрг/с — в `attrs['akasofu']`.

### `calculate_peak_dhdt`

Находит максимум `|dH/dt|` в скользящем окне и записывает его в `peak_dhdt` (нТ/мин). Параметр `window_seconds`, несмотря на историческое название, задаёт ширину окна в отсчётах. По умолчанию это 10 отсчётов минутного ряда. В `attrs['peak_dhdt']` сохраняются пик, его время и уровень `low`, `medium` или `high`. Границы уровней — 50 и 200 нТ/мин.

### `detect_substorm_onset`

Ищет начало устойчивого падения индекса SML. Нужен столбец `SML` из таблицы индексов SuperMAG (`data_type='indices'`). По умолчанию кандидат регистрируется, когда `dSML/dt` остаётся ниже −50 нТ/мин не менее трёх минут. Порог и длительность задаются через `drop_threshold_nT_per_min` и `min_duration_min`. Временем начала считается первый отсчёт первого подходящего интервала.

Функция добавляет столбец `sml_dh_dt`. В `attrs['substorm']` сохраняется результат поиска с оценкой по величине превышения порога. Вывод «кандидат не обнаружен» относится к выбранному окну и критерию этого детектора.

### `calculate_eej_index`

Оценивает вклад экваториального электроджета по разности `EEJ = H(экваториальная станция) - H(опорная станция)`. Обычно используют две станции INTERMAGNET. Подбор пары важен для интерпретации: опорная станция должна находиться вне области электроджета, обычно на расстоянии около 6–8° по широте, при сопоставимом фоне Sq.

В `df` передаётся таблица экваториальной станции, в `reference` — данные опорной станции с H либо с X и Y для его расчёта. Допускается также готовый ряд `H_reference`. Разность в нТ записывается в `eej_index`. Среднее, пик и время пика сохраняются в `attrs['eej']`.
