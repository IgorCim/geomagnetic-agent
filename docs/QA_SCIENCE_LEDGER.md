# Научные эталоны для QA

Дата: 03.11.2026. Это реестр подготовки независимых проверок, **не научный сертификат**. Базовый код eca4cb7. Общая программа: [QA_MASTER_PLAN.md](QA_MASTER_PLAN.md). Для строк ниже, кроме явно воспроизведённого Ey, статус **ORACLE_PENDING**: ещё нужны утверждённые контрольные числа, допуски и исполняемые независимые тесты.

## 1. Расчёты агента

| Семейство / registry metric | Что обязан проверить независимый эталон |
|---|---|
| H/F/D/I | H=hypot(X,Y), F=hypot(H,Z), D=degrees(atan2(Y,X)), I=degrees(atan2(Z,H)); все четверти, нули, NaN, огромные значения, nT/deg. Вектор (3,4,12) даёт H=5,F=13. Измеренная scalar F и вычисленная норма XYZ на реальных данных могут различаться. |
| Статистика | min/max/mean/median, выборочная std с ddof=1, count/missing после оговорённого numeric coercion; пустой ряд, одна точка, константа, Inf, строки, пропуски. Эталон не должен импортировать функцию агента. |
| baseline/delta/anomaly, sigma detector | Точный выбор окна и границ, night/full, median/mean, UTC против местного времени, маска выбросов, постоянный ряд. «Выброс» не равен доказанной магнитной буре. |
| dH_dt и legacy-функции | Разность делится на фактический интервал времени с явно заданными единицами. Проверить разные шаги, разрывы, дубликаты и перестановку timestamp. Отдельно проверить старую geomag_math.calculate_dst_proxy: название не доказывает эквивалентность physics_engine.calculate_dst_proxy. |
| sq_baseline | Сейчас константы по ночному окну; не заявлять полноценной моделью суточной Sq-вариации. Эталон отдельно вычисляет компоненты baseline и производные нормы. |
| deltas | Вычитание согласованного baseline; единицы, пропуски, исходные данные не меняются. |
| gic | Производная и её временной масштаб; назвать proxy, а не током в амперах без модели проводимости и сети. |
| dst_proxy | Обоснование выбранных станций, baseline и весов; не подменять официальный Kyoto Dst. |
| ey_coupling | **CONFIRMED_FAIL по масштабу**: 400 km/s × -5 nT код выдаёт -2000 с меткой mV/m. Размерность требует множитель 10^-3: -2 в конвенции произведения кода. Стандартное OMNI Ey=-V×Bz×10^-3 даёт +2. Знак и термин coupling должны получить отдельный согласованный контракт; простой перевод масштаба не завершает научную приёмку. |
| detect_ssc (schema alias ssc_flag) | Искусственные ступени, плавный тренд, шум, пропуски и границы; временные окна в секундах/минутах, baseline, порог. Детектор-кандидат не равен официальному каталогу SSC. |
| burton_coupling | Сверить конкретную реализацию с выбранной версией уравнения, давлением, порогом инжекции и постоянной распада. Проверить шаг интегрирования/устойчивость на разных сетках. Упрощение нельзя объявлять точной реализацией Burton 1975. |
| akasofu_epsilon | Полная выбранная формула, SI conversion, B и clock angle, квадранты atan2, sin(theta/2)^4, длина связи и её единицы. Оригинальная публикация идентифицирована; страница уравнения и численные эталоны ещё требуют сверки. |
| peak_dhdt | Производная nT/min либо явно иная единица; window_seconds должен соответствовать времени, а не случайному числу строк. Плато, импульс, редкая/нерегулярная сетка. |
| substorm_onset | Метод и пороги, положительные/отрицательные синтетические события, ложные срабатывания. Научная валидация требует независимой размеченной выборки, а не только специально сконструированного импульса. |
| eej_index и отдельный calculate_eej_index | Обоснованная экваториальная/референсная пара, baseline, совместное UTC-покрытие, разность H, разные сетки/длины. Не использовать IRT как фиктивную экваториальную станцию ради запуска. |
| Координаты, LT, MLT, bins | Сверять именно реализованную модель наклонного диполя, не выдавать её за IGRF/AACGM. LT: longitude/15 с переходом даты; MLT: 0/24, округление и перенос минут, отрицательные долготы, bins на границах. |

Каждый oracle хранит: версию уравнения, источник и страницу, входные/выходные единицы, систему координат, допустимое разрешение, набор контрольных точек, абсолютный/относительный допуск и причину допуска. Отдельный специалист должен проверить физическую применимость там, где одного численного совпадения недостаточно.

## 2. Безопасный язык формул

19 зарегистрированных функций: abs, acos, asin, atan, atan2, cos, degrees, exp, hypot, log, log10, maximum, minimum, power, radians, sign, sin, sqrt, tan. Проверять каждую и композиции, арность, broadcast, операторы, pi/e/nan, область определения, NaN/Inf, overflow, деление на ноль и предел длины выражения.

Независимый ряд точных контрольных случаев: hypot(3,4)=5; sqrt(9)=3; sin(pi/2)=1; degrees(pi)=180; log(e)=1. Тригонометрические аргументы — радианы, если явно не сделано преобразование. Эти примеры сами по себе не покрывают весь DSL. Запрещённые AST, обращения к атрибутам/индексам, импорты и дорогостоящие выражения проходят отдельную защитную серию с ограничением времени и памяти.

## 3. Загружаемые продукты: определения и provenance

| Источник | Проверяемое содержание, а не обещание «весь сайт» |
|---|---|
| INTERMAGNET | IAGA-2002, коды компонент/станций, missing/fill, UTC, публикационный статус, единицы, календарные границы, cache/fallback provenance. |
| OMNI | Dataset/разрешение, time tags и уже выполненный поставщиком time shift, GSM/GSE-компоненты, fill и единицы. Не сдвигать время второй раз без основания. |
| Kyoto / Kp provider | Официальный Dst, фактический поставщик Kp, provisional/final/realtime, часовое/трёхчасовое разрешение. Интерполяция или повторение значений не создаёт новые наблюдения. |
| SuperMAG | SME/SML/SMU и сайты — конкретные реализованные продукты. Исторический успешный лог не доказывает нынешнюю доступность API. Не реализуем заново весь алгоритм поставщика. |
| NOAA | alerts/forecast/solar_events, фактическое окно и issue/valid time; отсутствие исторических записей в текущем коротком окне не равно отсутствию событий в прошлом. |
| ISWA | Конкретные HAPI-наборы, наблюдение против прогноза, покрытие и частичные отказы. Отключённый клиент карты не является сетевой проверкой, что NASA сегодня не восстановила продукт. |

«Все формулы со всех шести сайтов» — несоразмерное и неопределённое требование: там множество продуктов, которых агент не использует. Покрываем все собственные вычисления и преобразования агента и точные определения всех фактически загружаемых продуктов. Расширение на новые продукты оформляем отдельным объёмом работ.
