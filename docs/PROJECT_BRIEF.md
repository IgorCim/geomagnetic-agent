# Геомагнитный ИИ-агент: описание продукта и инженерной реализации

## Продукт и пользовательская задача

Это исследовательский прототип ассистента для геомагнитных временных рядов. Пользователь задаёт по-русски станцию, период и нужный результат; локальная языковая модель выбирает зарегистрированные операции. Python загружает данные, рассчитывает производные, строит интерактивные графики и собирает проект. При отсутствии данных или отказе поставщика система должна сообщать причину, сохраняя доступные результаты.

Практическая ценность — сократить ручную последовательность «найти данные → привести формат/время → вычислить → построить → подписать → разложить файлы → упаковать». MVP позволяет исследовать дни и станции в чате и повторять пакетные задания. Он не заменяет квалифицированную научную интерпретацию, официальные индексы и системы оперативного предупреждения.

Название SaaS описывает направление развития. Текущая поставка — Python-приложение с Gradio и локальными файлами; эксплуатационная платформа с организациями, платежами и изолированными заданиями ещё не построена.

## Архитектура

Модель — Qwen 2.5 14B Instruct GGUF Q4_K_M через llama-cpp-python. При явном запуске загружаются веса, модель остаётся в процессе. Коммерческий LLM API не используется. Для загрузки внешних геофизических данных по-прежнему нужен интернет; локальный inference не делает весь workflow автономным от сети.

Обычный запрос идёт через `run_agent`. Router выбирает релевантные схемы. Ответ модели разбирается из structured calls, тегов `<tool_call>` или поддерживаемых JSON-форм. Dispatch разрешает только известные инструменты из предложенного набора. Результат инструмента возвращается модели в сокращённом виде; полный DataFrame остаётся в Python.

FrameStore адресует таблицы строковыми handle, например `raw:irt:2024-09-10`, `derived:irt:2024-09-10`, `sw:omni:2024-09-10`. Регистр handle нормализуется. Семейство `raw` — alias последнего члена, а не способ обозначить сразу несколько дней. Это предотвращает перезапись одного дня другим при сравнении.

Scratchpad хранит краткую рабочую память текущего запроса и подсказки коррекции. По умолчанию обычный цикл ограничен 28 tool calls и 25 model rounds. Planner-пути имеют собственные бюджеты; один вызов матричного инструмента может выполнить много Python-операций. Поэтому лимит tool calls нельзя выдавать за общий лимит всех сетевых запросов или времени задачи.

## Два режима исполнения

В коротком диалоге модель последовательно выбирает инструменты. В больших заданиях LLMPlanner формирует структурированный план; конкретные задачи с полными аргументами исполняются напрямую. Большие однородные планы могут сворачиваться в матрицу «станция × дата». При `run_until_complete=True` исполнитель проходит станции и события, отмечает успешные/провалившиеся ячейки и вызывает экспорт.

Это осознанная граница ответственности: модель планирует, Python исполняет массовую работу. Успешный такой прогон доказывает работу планирования и исполнителя в заданных условиях, но не доказывает способность модели автономно удерживать сотни отдельных tool calls в одном контексте.

`apply_physics_formula` диспетчеризует 11 метрик: sq_baseline, deltas, gic, dst_proxy, ey_coupling, detect_ssc, burton_coupling, akasofu_epsilon, peak_dhdt, substorm_onset, eej_index. Часть имён доступна через aliases. `plot_magnetogram` существует как Python-функция, но отдельной схемой модели не выставлен. Это различие необходимо сохранять при описании продукта.

Ограниченный язык пользовательских формул разбирается через AST и белый список операций/функций, а не через выполнение произвольного Python. Он поддерживает арифметику над колонками и рядом NumPy-функций, числовые константы и ограничение длины выражения. Наличие такого ограничителя не заменяет аудит всех ресурсов и публичной безопасности сервиса.

## Данные, графики и происхождение результата

Основные ряды обсерваторий: X/Y/Z/F. H/D/I вычисляются через hypot/atan2; D/I выражены в градусах. Статистика включает min/max/range/mean/median/std и описание пропусков. Аномалии определяются относительно среднего и стандартного отклонения выбранного ряда; это статистическая процедура.

Графики Plotly сохраняются в HTML и отображаются через фиксированные gr.Plot. Для смешанных единиц используются отдельные панели. В длительных рядах возможен stride sampling; график не следует считать точной визуализацией каждого экстремума полного набора без проверки исходных данных. NaN не соединяются через connectgaps.

Проект использует дерево `<project>/<station>/<date>/`, CSV и manifest, индекс charts.json и source-теги имён файлов. В charts.json фиксируются данные графика, использованные handle и хеш файла. Экспорт добавляет CSV/HTML-индекс и export_manifest. Пользовательский layout ZIP не должен переименовывать канонические графики проекта. Повторный экспорт обновляет некоторые метаданные; утверждение «вообще ни один байт проекта не меняется» было бы слишком сильным.

В Gradio одновременно показывается до 12 превью; после текущих исправлений список скачивания сохраняет все графики чата. Частичный отказ не должен прятать уже созданные файлы. Результаты матриц берутся из успешных ячеек внутри разрешённого проекта.

## Интеграции и актуальное состояние

Шесть источников представлены специализированными клиентами: INTERMAGNET, NASA OMNI, Kyoto, NOAA, SuperMAG и NASA ISWA. Полный объём каждого сайта/API не реализован. [Матрица источников](SOURCE_COVERAGE.md) содержит точные поля, форматы, окна и недоступные возможности.

Сегодня старый SuperMAG indices endpoint отвечает HTTP 404. Исторический успешный прогон сохраняется как отдельное свидетельство старой интеграции; заявлять его результатом текущего API нельзя. ISWA HAPI и legacy-карта — разные возможности: карта отключена текущей веткой кода, наличие каталога HAPI не делает её доступной.

## Длинный диалог

Таблицы сохраняются между сообщениями внутри браузерной сессии. Каждое новое обращение модели получает короткую сводку предыдущих реплик и доступных handle. Полный transcript не подаётся целиком; scratchpad предыдущего запроса не является долговременной памятью.

Локально проверено сохранение данных после 14 HTTP-ходов с тестовой моделью. Понимание давнего контекста настоящей Qwen требует отдельной 20-ходовой приёмки. [LONG_CHAT.md](LONG_CHAT.md) отделяет состояние данных от языковой памяти и описывает ожидаемое поведение при неоднозначности.

## Подтверждения и ограничения качества

Исторический отчёт от 28.10.2026 описывает 300/300 графиков: 200 в матрице A, 50 в B и 50 в C; в контекстных стадиях также использовался SuperMAG. Это не научная проверка всех кривых, не стресс-тест всех 29 инструментов, не проверка UI и не аттестация текущего рабочего дерева. Более поздняя научная выборочная проверка имеет собственные ограничения.

Новый офлайн-baseline и проверки Gradio сохраняются отдельно с версиями и SHA-256. Настоящая модель, сетевые данные, browser rendering, корректность чисел и длительная работа проверяются разными слоями. [VALIDATION.md](VALIDATION.md) — реестр фактически выполненных проверок, [KAGGLE_ACCEPTANCE.md](KAGGLE_ACCEPTANCE.md) — воспроизводимый протокол оставшейся живой приёмки.

Вычислительные ограничения существенны: Ey имеет выявленное расхождение масштаба/подписи, ряд метрик предполагает минутную сетку, Sq/Dst/Burton/EEJ/MLT являются упрощениями. Они перечислены в [CODE_REVIEW.md](CODE_REVIEW.md). До отдельной коррекции и независимых эталонов нельзя продавать все физические результаты как аттестованные прогнозы.

## Путь к SaaS

Ближайшая инженерная граница — воспроизводимо показать актуальный Gradio и live-Qwen, не скрывая внешних отказов. Затем нужны: изоляция владельцев проектов/файлов, auth и управление доступом, транзакционное хранение/конкурентная запись, durable job queue с отменой/возобновлением, лимиты ресурсов, структурированная память исследовательской задачи, эксплуатационные метрики и отдельная научная валидация.

Эти пункты описывают ещё не выполненную работу. Сильная сторона текущего MVP — уже реализованная цепочка от естественного языка до проверяемых артефактов и управляемой пакетной обработки, с явным отделением модели от вычислений и источников.
