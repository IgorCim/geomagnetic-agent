## Что проверил HTTP-тест

Запущен production `build_demo` на 127.0.0.1 без share. У двух gradio_client разные session_hash. Использованы production run_agent, handlers, state, queue, сериализация и файловые маршруты; только brain и station loader заменены предсказуемыми тестовыми исполнителями.

1. Сессия A загружает frame через button endpoint и строит Plotly через textbox-submit endpoint.
2. HTML реально скачан по выданному Gradio URL; HTTP 200 и внутри присутствует Plotly.newPlot.
3. Ещё 12 обращений к статистике: всего 14 последовательных ходов с сохранением frame и transcript.
4. Сессия B не находит handle сессии A.
5. Создание пустого проекта, обновление выбора, выбор проекта, сборка ZIP, скачивание и `ZipFile.testzip()`; export_manifest присутствует.
6. Пустое сообщение не ломает событие очереди.

В браузере отдельно выполнены загрузка и построение графика кнопкой, затем отправка следующего сообщения через Shift+Enter; видны реальный Plotly, оси и ссылка HTML. Ctrl+Enter при повторной проверке не отправил сообщение, первоначальная подсказка исправлена. Условие Shift+Enter для многострочного поля также сверено с установленным frontend Gradio. Отправка через UI не подменялась вызовом endpoint в этом визуальном шаге. Данные на этой странице синтетические и подписаны TEST FIXTURE, поэтому это доказательство работы интерфейса, а не материал для видео о настоящем агенте.

Ранние служебные каталоги без итогового result/run.json не являются успешными прогонами. При подготовке HTTP-harness исправлены два его ожидания: Plotly возвращается внутри gr.update.value, а dropdown надо обновить перед выбором нового проекта. Эти ошибки harness не выдаются за дефекты модели.
