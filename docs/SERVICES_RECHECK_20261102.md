Проверены официальные страницы и реальные HTTP-ответы. Production-загрузчики не изменялись: подтверждённого работающего нового способа для требуемых продуктов не найдено. Вывод ограничен перечисленными адресами; утверждать, что нигде не существует иной службы, нельзя.

## SuperMAG

Официальная [страница Web Services](https://supermag.jhuapl.edu/mag/?tab=api) открывается, но по-прежнему описывает inventory.php, data.php и indices.php. Встроенная документация содержит серверные PHP warnings о ненайденных include-файлах. Ссылка на предлагаемый Python-клиент возвращает 404.

| Проверка | Фактический результат |
|---|---|
| Главная страница и страница Web Services | HTTP 200, HTML |
| /services/indices.php, публичный запрос | HTTP 404 |
| indices.php с заданным пользователем logon, окно 60 секунд | HTTP 404 |
| inventory.php и data-api.php с logon | HTTP 404 |
| data.php из официальной документации, с logon | HTTP 404 |
| Официальная ссылка /mag/lib/content/api/supermag-api.py | HTTP 404 |
| /hapi/indices_all/catalog | HTTP 200, но **HTML Maintenance Page**, не HAPI JSON |

Логин в сохранённых диагностических URL и телах ответа замаскирован. HTTP 404 появляется и с предоставленным logon: это не результат локальной ошибки missing_logon. Серверная страница maintenance согласуется с продолжающимися техническими работами, но не доказывает точную причину, дату начала, план миграции или срок завершения. «Новый API уже готов» этой проверкой не подтверждается.

Поэтому сейчас не стоит заменять старый клиент на непроверенный адрес или выдавать альтернативный продукт за SME/SML/SMU. Следующий gate миграции: официальный рабочий endpoint → реальный короткий ответ → схема и единицы → timestamps/NaN → сравнение с известными данными → loader tests → live tools → два исторических окна и полный gate.

Историческое свидетельство теперь есть: исходный скачанный notebook найден локально, его SHA-256 и ключевые строки ячейки 10 повторно сверены с [реестром](evidence/stress_kaggle_summary.json). [Сохранённый output stress_3ffd1r21](evidence/stress_3ffd1r21_cell10_output_redacted.log) подтверждает зафиксированные на 28.10.2026 статусы 300/300 и два успешных окна по 21 600 строк. Это допустимо прямо указать в README как результат того запуска; он не подтверждает нынешнюю доступность и численную корректность всех данных.

## NASA ISWA Ground Magnetic Perturbation Maps

На [официальной странице NASA](https://ccmc.gsfc.nasa.gov/tools/ISWA/) описаны миграция приложения, HAPI и файловые REST API. Рабочий WMS для ground_mag_perturbation там не заявлен. Прямой GetCapabilities к старому wmts/wmts.cgi вернул HTTP 403. Это отказ доступа, а не официальный ответ об окончательной декомиссии.

Проверены данные нового каталога, а не только HTML-оболочка:

- `/api/info?mode=active,event,retired`: 3078 feeds;
- `/meta/library/cygnet-search.json`: 408 cygnets;
- точное имя `ground_mag_perturbation` не найдено;
- родственные Solar Shield geomagnetic/geoelectric perturbation продукты 592/593/603 помечены **retired**.

Эти родственные продукты не объявляются доказанно тем же WMS-слоем: точное соответствие не установлено. Рабочей опубликованной замены именно требуемой карты не найдено. Снимать заглушку или подставлять другую картинку сейчас оснований нет. Следует описывать состояние как «legacy-карта недоступна в текущей интеграции; замена не подтверждена», а не утверждать без документа NASA, что организация навсегда отключила конкретный слой.
