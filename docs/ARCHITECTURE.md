# Архитектура

## Путь одного запроса

1. [gradio_app.py](../gradio_app.py) принимает текст и состояние браузерной сессии, готовит краткую историю и передаёт запрос исполнителю. Модель может обслуживать несколько диалогов. У каждого клиента своя память таблиц.
2. [chat_session.py](../chat_session.py) представляет запрос как Request, выделяет явно указанные станции, даты, компоненты, handle и запреты. SessionMemory связывает продолжение с предыдущим результатом. Для однозначной статистики обработчик может вызвать get_statistics напрямую. Ошибочное распознавание SML как станции проявляется именно на границе языка и проверки обязательств.
3. [agent_core.py](../agent_core.py) выбирает схемы по задаче, формирует сообщения и вызывает LlamaBrain. Ответ с tool calls проходит разбор, проверку доступности инструмента и согласованности аргументов. Обработчик находит таблицу и выполняет операцию. Полный DataFrame остаётся в FrameStore. Модель получает краткий результат, handle и при необходимости подсказку для исправления.
4. Scratchpad ведёт выполненные шаги, факты, недостающие результаты и ошибки текущего запроса. Исполнитель может продолжить цикл, завершить его по достижении цели, остановить повторяющиеся ошибки либо исчерпать бюджет. Итог сочетает текст и факты инструментов. Ошибка на этом последнем этапе может дать ложный статус при правильном расчёте.
5. Gradio возвращает ответ, журнал, превью, пути для скачивания и обновлённое состояние. Интерфейс показывает до 12 превью. Список файлов позволяет получить остальные графики.

## Три масштаба памяти

Контекст llama.cpp при приёмке — 16384 токена. Интерфейс выбирает до четырёх предыдущих ходов чата для текстовой истории. Внутри одного запроса сохраняются шесть последних обменов с инструментами и краткие численные результаты. В scratchpad отображается до 12 handle. Отдельно FrameStore сохраняет таблицы между репликами, поэтому обращение к конкретному handle возможно и после вытеснения текста из контекста. Двадцать сообщений в тесте измеряют способность продолжать задачу при таких условиях.

## Пакетное исполнение

[agent_planner.py](../agent_planner.py) содержит Planner и LLMPlanner. Второй запрашивает JSON с подзадачами и аргументами. При непригодном выводе предусмотрен резервный разбор. [agent_state.py](../agent_state.py) описывает TaskStep и SessionState. Для повторяющейся работы используется матрица станций и событий с действиями и общими аргументами. create_task_matrix задаёт структуру, process_matrix_batch обрабатывает ячейки, фиксирует покрытие и собирает архив. Путь JSON позволяет продолжить существующую матрицу. Состояние на диске и содержимое матрицы определяют, какие результаты можно считать завершёнными.

## Проект и экспорт

Память таблиц живёт в процессе. Workspace связывает материализованные артефакты с каталогом проекта. CSV, JSON-манифесты и charts.json обеспечивают связь между станцией, временем и графиком. При экспорте каталоги назначения сопоставляются с путями внутри проекта. Проверяются границы каталога, пересечения путей, совпадения имён и фактический результат отбора. Сведения о размещении попадают в манифест архива. В Gradio отдельно доступны дерево на диске, готовый пользовательский архив и ручное создание полного ZIP. Разделение сессионных таблиц было проверено на двух устройствах. Многопользовательская авторизация файлов остаётся отдельной задачей.

## Где живут инструкции модели

Рабочие определения находятся в agent_core.py и agent_planner.py. В [prompts/](../prompts/) сохранены тексты и схемы для ревью версии 9a9e211. Динамическая часть строится на каждом шаге из доступных схем, вопроса, scratchpad и результатов. Под «самообучением» в комментариях к Scratchpad понимается коррекция следующего действия по ошибке и hint в текущей задаче. Обновление весов в этом контуре отсутствует.

## Проверка архитектурных границ

ScriptedBrain позволяет тестировать dispatch, работу с файловой системой и обработку ошибок воспроизводимо. Проверки HTTP Gradio дополнительно проверяют передачу состояния через UI. Живой Qwen проверяется отдельно по вызовам и пользовательскому ответу. Научная корректность требует независимых эталонов. [Журналы, сценарии и критерии](TESTING.md).
