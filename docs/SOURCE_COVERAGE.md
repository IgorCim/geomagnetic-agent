# Покрытие источников данных

Проверено по текущему коду и публичным службам 01.11.2026. Слово «поддерживается» ниже означает наличие конкретного клиента и обработки результата. Оно не означает доступность всех данных, всех функций сайта или SLA поставщика.

## Почему нельзя написать «четыре сайта сделаны на 100%»

У четырёх основных интеграций есть законченные пользовательские цепочки для выбранных задач. Однако каждый поставщик предлагает больше продуктов, форматов и операций, чем реализовано в этом MVP. Без зафиксированного перечня требований процент покрытия не определён. SuperMAG и ISWA также реализованы выборочно; отличие — в текущем состоянии отдельных адресов и продуктов, а не в наличии/отсутствии «настоящего API».

Приложение действительно обращается к машиночитаемым службам: GINServices, HAPI, JSON NOAA и legacy Web Services SuperMAG. Это не универсальный браузерный агент, который изучает любой сайт и самостоятельно осваивает его функции.

## INTERMAGNET

Код: `intermagnet_loader.py`.

Реализованы GetCapabilities, объединение каталогов Edinburgh/Kyoto, GetData с ориентацией XYZF, JSON/IAGA-2002, даты и состояния публикации, запросы чанками по 31 дню, повторные попытки, сортировка, удаление дубликатов времени, кэш Parquet и запись CSV при отсутствии pyarrow. При отсутствии запрошенного состояния выполняется fallback. Поэтому запрос definitive не гарантирует, что фактически получен definitive.

Не реализованы все GIN-операции: каталоги доступности по датам, времена модификации, анализ задержек сети и прочие административные/статистические службы. Нет автоматического подтверждения полноты каждого дня по всем ожидаемым минутам. В кэше известны ограничения восстановления метаданных и чтения CSV fallback; см. разбор кода. Секундный режим присутствует во входном контракте, но все вычисления нельзя автоматически считать корректными для секундного ряда.

Публичный каталог в текущей проверке: HTTP 200. Это не тест каждого observatory/date.

Первичные источники: [INTERMAGNET Data Downloads](https://intermagnet.org/data_download), [полный перечень служб GIN](https://imag-data.bgs.ac.uk/GIN_V1/).

## NASA CDAWeb / OMNI

Код: `space_weather_loader.py`, `fetch_solar_wind`.

Поддержаны `OMNI_HRO2_1MIN` и резервный `OMNI_HRO_1MIN`. Метаданные HAPI определяют имена столбцов и fill-значения. Выход: timestamp, V, Np, T, Bx, By, Bz. By/Bz — GSM; Bx исходно BX_GSE. Пропуски превращаются в NaN. `align_solar_wind` совмещает ряд с временной осью станции и допускает ограниченную интерполяцию.

Не реализованы остальные миссии и наборы CDAWeb, произвольный выбор параметров, универсальный HAPI-клиент, живые ACE/DSCOVR-потоки, автоматическое установление причинности или прогноза. Резервирование набора не является гарантией заполнения дыр во всех полях.

Научно важная деталь: high-resolution OMNI уже перенесён к носовой части земной ударной волны; время соответствует прибытию. Называть его просто «сырыми измерениями L1» или повторно добавлять фиксированную задержку без обоснования нельзя. Текущий default lag=0 соответствует отсутствию дополнительного ручного сдвига.

Проверка metadata: HTTP 200. Первичные источники: [HAPI metadata OMNI](https://cdaweb.gsfc.nasa.gov/hapi/info?id=OMNI_HRO2_1MIN), [описание временной привязки NASA](https://omniweb.gsfc.nasa.gov/html/HROdocum.html).

## WDC Kyoto

Код: `space_weather_loader.py`, `fetch_geomagnetic_indices`; также резерв станционных данных в INTERMAGNET loader.

Поддержаны `hour_dst` и `hour3h_kp`. Dst и Kp совмещаются по часам; одно трёхчасовое значение Kp распространяется на три часа. Это удобство сопоставления, а не три независимых измерения и не переход к часовому разрешению Kp.

Не реализованы остальные индексы каталога — AE/AL/AU, ASY/SYM, ap/Ap и другие продукты, universal dataset selection, version-pinned выбор и сохранение всех полей качества/версии. Публичный каталог сейчас отвечает HTTP 200.

Источник: [официальный HAPI Kyoto с каталогом и форматами](https://wdc.kugi.kyoto-u.ac.jp/hapi/). Kp в этом сервере атрибутируется GFZ, а не объявляется собственным индексом Kyoto.

## NOAA SWPC

Код: `noaa_swpc_loader.py`.

Поддержаны три операции: фильтрация геомагнитных alerts/warnings, текущий прогноз Kp и каталог GOES X-ray flares за последние семь дней. Преобразуются времена и шкалы G1–G5; у прогноза выделяется максимум. Название `fetch_solar_wind_forecast` историческое: функция получает прогноз **Kp**, а не скорость, плотность и IMF солнечного ветра.

Не реализованы все продукты SWPC: исторический поиск вспышек за произвольный год, все R/S/G-уведомления, полный набор GOES, модели, карты и продукты спутников. Вопрос о мае 2024 к семидневному каталогу не даёт исторической справки: пустая выборка не означает отсутствия вспышек в мае 2024.

Сегодня alerts и forecast: HTTP 200. Проверка адреса не подтверждает каждое преобразованное поле. Источник: [официальный каталог JSON-продуктов NOAA](https://services.swpc.noaa.gov/products/).

## SuperMAG

Код: `supermag_loader.py`.

Реализован клиент трёх старых путей: `data-api.php`, `indices.php`, `inventory.php`. Станционные данные — возмущённые dX/dY/dZ и географические компоненты с уже удалённой базовой линией; это не абсолютные X/Y/Z INTERMAGNET. Индексы ограничены SME/SML/SMU. На один data-запрос в текущем коде установлен предел **24 дня**. В старых описаниях встречается 32 — это устаревшее число.

Логин хранится на FrameStore браузерной сессии и передаётся загрузчику. У CLI остаётся fallback из SUPERMAG_LOGON. В новой диагностике параметр logon в URL маскируется; поле пароля и секреты не должны попадать в видео.

01.11.2026 выполнен публичный запрос к `https://supermag.jhuapl.edu/services/indices.php?python&nohead`: HTTP **404**. Текущий клиент этот адрес использует. Это свидетельство отказа legacy-пути, не доказательство закрытия всего SuperMAG. Авторизованная загрузка и новый API в этом прогоне не проверены. Переход на другую службу без анализа формата/правил не выполнен.

Исторически в ACCEPTANCE.md зафиксированы два успешных 15-дневных окна по 21 600 строк. Это прошлое состояние интеграции; найденный Kaggle notebook output и его ограничения разобраны в [docs/evidence/README.md](evidence/README.md). Это сохранённый output, а не независимый raw stdout; для полного подтверждения всё ещё нужны исходный лог и артефакты. Источник общей интеграции: [SuperMAG](https://supermag.jhuapl.edu/); текущий 404 подтверждён сохранённым локальным HTTP-отчётом, а не догадкой о логине.

## NASA ISWA

Код: `iswa_loader.py`.

Выбраны HAPI-наборы `NOAA_KP_P3H` и `dst_quicklook`. Окно формируется относительно текущего UTC: назад 24 часа, вперёд 48, вывод с шагом три часа. У Kp различаются observed/predicted/estimated/reported. Dst quicklook — наблюдение/nowcast; прогноз будущего Dst здесь отсутствует. Недоступность Dst не обязана обрушить доступный Kp.

Ветка `get_ground_perturbation_map` по умолчанию возвращает `service_decommissioned` **до сетевого запроса**. Сохранившийся WMS-клиент и синтетический PNG нужны для тестов/совместимости. Значит, ответ этого инструмента подтверждает политику текущего кода, но сам по себе не доказывает официальную декомиссию продукта NASA. В документации следует говорить «legacy-карта не поддерживается текущей интеграцией».

Не реализованы весь каталог HAPI, cygnets, поиск файлов, data-tree, universal dataID routing и новые файловые API ISWA. Официальная NASA-страница описывает обновление приложения и дополнительные API; это отдельный объём работ. Сегодня каталог HAPI: HTTP 200, а не проверка успешности обоих выбранных data-запросов.

Источник: [NASA CCMC: ISWA и её Web Services](https://ccmc.gsfc.nasa.gov/tools/ISWA/), [HAPI catalog](https://iswa.ccmc.gsfc.nasa.gov/hapi/catalog).

## Как читать доказательства

`verification/20261101T124759Z_sources/result.json` содержит адреса, время, статусы и формы публичных ответов. Его область — reachability. Сквозной success требует дополнительно: получить требуемое окно → разобрать данные → проверить заполненность/время/единицы → вызвать инструмент → проверить график/архив. Исторический success и сегодняшний HTTP 200 не заменяют эту цепочку.
