## Вклад последних правок

В 5dcb3b9 Gradio начал передавать `routing_query=question`: старые темы перестали занимать ограниченный набор инструментов. Но отдельное состояние намерения/первой даты и разрешение ссылок не были добавлены. Поэтому исправление неполное: оно исправило загрязнение выбора инструментов историей, но оставило модель с историей и router без разрешённого смысла местоимений. Последующие запросы нельзя считать проверенными только по тесту явного сравнения H с Bz/V.

Alias `dst → dst_proxy` найден и в 3bca4a1. Диагностика исторического тела `_selection_plan` с неизменёнными зависимостями маршрутизации даёт тот же ошибочный набор Kyoto. Это узкое сравнение выбора инструментов, не запуск старой Qwen или всего старого приложения. Ограничение Gradio четырьмя парами также существовало до 5dcb3b9. Исправления статистики действительно устранили другой отказ — приведение Dst/Kp к несуществующим DST/KP; эти два дефекта не следует смешивать.

Снижение temperature или увеличение окна сами по себе не обеспечат правильную дату, завершённую загрузку и достоверность итоговой сводки. В коде уже temperature=0.1; это не строгая детерминированность.

## Почему 1017 тестов не дали этой гарантии

В `tools/verify_gradio.py` selector заменён на выдачу всех схем, а TestBrain получает заранее заданные handle. Этот тест проверяет реальную HTTP-очередь, session state, сериализацию, downloads и разделение двух сессий; рабочий router и понимание ссылок моделью он не проверяет. Отдельные unit-тесты router существуют, но не покрыли конфликт Dst с dst_proxy и эти неоднозначные продолжения. Такие результаты не равны успешным двадцати ходам настоящей Qwen.

Отказ с BOU и выдуманная дата — неприемлемое поведение даже при сложной формулировке. Ошибка инструкции тоже на стороне автора сценария: старый список смешал пользовательские сообщения с указаниями проверяющему и объединил пункты 6–12. Пользователь воспроизвёл предоставленный текст. В LONG_CHAT.md теперь один набор двадцати отдельных сообщений; старые immutable GitHub URL продолжают показывать старый документ.

## Порядок ремонта и критерии

1. Исправить различение реального индекса Dst и явно запрошенного dst_proxy; проверить короткий Kyoto, Kyoto+stats+plot и явный proxy с разными формулировками.
2. Ввести ограниченное структурированное состояние сессии: подтверждённый первый запрос станции/дня, активные station/date/handle, результаты выполненных операций и созданные файлы. Источником состояния должны быть успешные tool results, а не свободный текст модели. Состояние должно принадлежать браузерной сессии и обновляться/очищаться явно.
3. До выбора инструментов разрешать ссылку по этому состоянию; при неоднозначности спрашивать. Запретить молчаливую подмену даты/станции при выполнении. Для отрицательного теста передавать настоящий заведомо отсутствующий handle.
4. Проверять выполнение запрошенной операции: «загрузить BOU» не выполнено, пока соответствующий fetch/frame не подтверждён. Отказ stats не разрешает численные выводы; попытка plot не равна существующему HTML.
5. Строить сводку использованных данных/файлов по реестру реальных результатов и проверке существования файлов, отмечая недоступные/удалённые. Не выдавать shell-пример за исполненную проверку.
6. Добавить интеграционный replay всего сценария с рабочим selector без подмены на все схемы: переход IRT→BOU→IRT, забытый первый день, январская таблица-приманка, отрицательный handle, восстановление и сводка. ScriptedBrain должен намеренно выбирать неправильную дату, пропускать fetch и выдумывать успешный текст: приложение должно отказывать/уточнять, а не принимать это за PASS. Проверить две независимые сессии, очистку и сбой запроса.
7. После изолированных тестов и CI провести короткую живую проверку изменённых случаев с сохранением журналов. Затем двадцать отдельных ходов настоящей Qwen. Повтор полного 300-chart stress не заменяет семантику диалога.

Это инженерный план, не утверждение, что перечисленные механизмы уже реализованы. До их проверки длинный разговор для научной работы и портфолио не принят. Полный автоматический rollback на старую версию также не доказан как решение: часть причин присутствовала раньше.
