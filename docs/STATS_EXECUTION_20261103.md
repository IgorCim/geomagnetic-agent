## Решение для статистики

Защита предотвращала неверный расчёт, но всё ещё просила модель повторно выбрать уже известные параметры. Для простой статистики по существующей таблице это лишняя неопределённость.

Теперь Gradio проверяет возможность прямого исполнения: операция — только описательная статистика, компоненты распознаны, таблица однозначно определена и существует, дата/станция/явный handle проверены. Выполняется один get_statistics через существующий исполнитель полностью заданных TaskStep. Этот механизм уже используется в планировщике; новый путь не содержит тестовой модели или заранее заданных чисел. В журнале остаются аргументы, факт исполнения и результат настоящего инструмента. Результат заново вычисляется из DataFrame, не берётся из текста истории.

Модель не вызывается и не может снова выбрать H вместо Y, запросить повторный fetch либо продолжить после выполненной статистики. Ошибка инструмента терминальна: она показывается без свободного повторного выбора другой таблицы/компонента. Пустой success-payload не принимается за рассчитанную статистику.

Запрос с отсутствующей таблицей, построением графика, H/D/I вместе с другими действиями, несколькими датами, фильтрацией по времени или специальным округлением сохраняет прежний модельный путь. Новый обработчик намеренно не заменяет такие задачи упрощённым расчётом всего дня. Понимание всех форм естественного языка этим не гарантируется.

Таблицы, расчётные формулы и SYSTEM_PROMPT не менялись. Изменены выбор пути одиночного запроса и сбор свидетельств прямого вызова статистики. Массовый stress не запускался.

## Графики: только исследование

Компоновка не менялась. Чтение кода подтверждено inspect объектов Plotly через `python -B tools/review_plot_layout.py`. В записи verification/20261103T080744Z_plot_layout/result.json есть SHA-256 неизменённого geomag_plotter.py. Использованы синтетические таблицы; HTML не создавались и не отрисовывались.

| Вызов | Панели/оси Y |
|---|---|
| plot_components(X,Y,Z) | Одна общая ось, три кривые в nT |
| plot_components(H,F) | Одна общая ось, две кривые в nT |
| plot_components(H,D,I) | Три панели: набор содержит разные единицы; каждая компонента получает свою панель |
| plot_components(D,I) | Одна общая ось в deg |
| plot_components(Dst,Kp) | Две панели: nT и безразмерный индекс |
| plot_space_weather_comparison(H,Bz,V) | Три панели; наземная H отделена по смыслу, Bz и V разделены по единицам |

Следовательно, одинаковые единицы не являются единственным правилом для всех инструментов. При H/D/I две угловые компоненты также разделены, потому что весь набор mixed-unit. В специализированном сравнении H и Bz разделены, несмотря на nT у обеих. Это детерминированные правила кода, не свободный выбор компоновки моделью внутри одного вызова.

Формулировка влияет на выбор инструмента, набора компонентов и числа вызовов. Несколько вызовов plot_components по одной компоненте дадут несколько самостоятельных файлов; один вызов с XYZ — общий график. Один HTML также может содержать несколько панелей: счётчик файлов не равен счётчику панелей. У plot_components нет параметра, который по просьбе модели переключает одинаковые единицы на независимые панели. Для прошлого случая «XYZ на трёх панелях» без его HTML/журнала точный вызов не установлен.

Общие шкалы XYZ и H/F могут скрывать малые вариации на фоне разных абсолютных уровней. Изменение отображения требует отдельного решения пользователя — оно здесь не выполнялось. Сырые значения не нормализовались и не вычитались.

## Логи и следующий короткий шаг

В Gradio раскрыть «Журнал вызовов инструментов» сразу после нужного ответа, прежде чем отправлять следующий вопрос. Он показывает последний запрос. Для печати дальнейших вызовов в выводе текущей Kaggle-сессии можно отдельной ячейкой выполнить:

```python
import gradio_app as ga
ga.VERBOSE = True
print("Журнал дальнейших вызовов включён в вывод Kaggle")
```

Это переключение существующего диагностического флага: код с GitHub не обновляется и brain не перезагружается. Для отключения — ga.VERBOSE=False. Native verbose модели отдельно не включается. Для публикации журнала не вводить в текст запросов секреты.

После публикации и CI нового кода нужен свежий kernel и ячейки 1–6 → 8; старые файлы/веса не удалять. Достаточно загрузить BOU за 2024-09-10, затем отдельно попросить статистику X/Y/Z/F/H без повторной загрузки и сохранить журналы. Для полностью определённых запросов ожидается один плановый get_statistics и ноль модельных раундов. Ошибку данных/инструмента нужно сохранить как ошибку, не обходить другим handle. Полные 20 сообщений и 300 HTML для проверки этого изменения не обязательны.

Прежний stress_68jr7z5e остаётся свидетельством 300/300 canonical HTML и пяти источников; SuperMAG пропущен. Это не полноценный six-source PASS и не доказательство бесконечного контекста или любой научной интерпретации.
