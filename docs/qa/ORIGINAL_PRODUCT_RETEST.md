Это не новая замена тестов 29 инструментов, 20 ходов и формул. Здесь собраны
исходные запросы, на которых обнаружены последние продуктовые ошибки.
Текст запросов ниже сохранён; подготовка отделена от проверяемого запроса.
Каждый блок выполняется в отдельном новом чате. Внутри блока чат не сбрасывать.
Сохранить HEAD, журнал вызовов, ответы и скачанные файлы.

## A. Исходный ZIP-запрос — 1 сообщение

```text
Создай отдельный проект qa_zip_123 и загрузи данные INTERMAGNET станции IRT
за 2024-09-10. Построй три отдельных HTML-графика: X, Y и Z.
Сохрани все три графика в этом проекте.

Затем экспортируй проект через export_project в ZIP qa_zip_123.zip.
Внутри архива сделай ровно три пользовательские папки верхнего уровня
с буквальными именами "1", "2" и "3".

В папку "1" положи только HTML-график X.
В папку "2" положи только HTML-график Y.
В папку "3" положи только HTML-график Z.

Для каждой папки передай в folders точный относительный путь к нужному
HTML-файлу. Не используй шаблоны, которые могут захватить другие файлы.
Служебные метаданные экспорта в корне ZIP допустимы.

После успешного экспорта укажи имя созданного ZIP и какой график лежит
в каждой папке, чтобы я мог скачать архив через Gradio и проверить его.
```

Скачать именно `qa_zip_123.zip`, а не `full_project_….zip`.
Ожидается `1/<HTML X>`, `2/<HTML Y>`, `3/<HTML Z>` без промежуточных
станции/даты. В каждом один HTML с нужной компонентой. Служебные файлы в корне
допустимы. Исправленная неудачная попытка должна оставаться в журнале,
но не выдаваться за окончательный отказ. Итог обязан показывать реальные пути.

## B. Смена H → Y → X — 3 сообщения подряд

```text
Загрузи INTERMAGNET BOU за 2024-09-10 и получи статистику H инструментом.
```

```text
Для BOU за 2024-09-10 теперь нужна статистика Y. Используй уже загруженные данные.
```

```text
Из той же таблицы получи минимум, максимум и медиану X инструментом. Не скачивай повторно.
```

Ожидаются реальные get_statistics для H, Y, X. Последний вызов — X из BOU
2024-09-10 без пробной подмены H и без повторной загрузки. Если подготовка
не получила BOU, зависимые запросы отмечаются BLOCKED, а не FAIL инструмента.

## C. Раскладки графиков и счётчик — подготовка + 3 сообщения

```text
Загрузи INTERMAGNET BOU за 2024-09-10 и получи статистику H инструментом.
```

```text
Построй X/Y/Z для BOU за 2024-09-10 как три отдельные панели одна под другой, в одном HTML. У каждой панели своя вертикальная шкала. Используй готовые данные.
```

```text
Теперь построй X/Y/Z из той же таблицы тремя отдельными HTML-файлами, по одной компоненте в каждом.
```

```text
Теперь наложи X и Y из той же таблицы в одной панели на общей шкале nT. Подпиши обе кривые.
```

Проверять HTML, а не только количество файлов: сначала три независимые панели
в одном HTML, затем три HTML, затем одна панель X/Y. Нижний rangeslider не
считается второй компонентой. Последний ответ должен учитывать один запрошенный
график, даже если до успешного вызова была отклонённая попытка.

## Отдельное новое требование: произвольная структура ZIP

Это не переформулировка A, а расширенная функциональность.
`folders` задаёт пути назначения, например `Отчёт`, `Отчёт/Сравнение/День2`;
`.` обозначает корень ZIP. В одной папке могут быть файлы разных станций/дат;
папка может одновременно содержать HTML и подпапку. Имена файлов выбирает код.

- `auto` у инструмента: точный файл размещается непосредственно в назначении;
  для выбранной директории или glob сохраняется исходное дерево.
- `direct`: все выбранные файлы непосредственно в назначении.
- `tree`: сохраняется путь источника внутри назначения.
- При совпадении имён из разных источников код добавляет детерминированный
  суффикс; оба файла сохраняются, соответствие отражается в `export_manifest.json`.
- Конфликт «файл и папка с одним путём», выход за каталог, отсутствующий источник
  отклоняются до замены существующего архива.
- Прямой Python API сохраняет старый default `tree` для совместимости.

Эти случаи покрывает `test_archive_layout.py`: сравниваются содержимое ZIP,
байты исходных файлов, индекс и манифест, в обычном и compact-режимах.
Это подтверждает возможности экспортёра, но не способность Qwen безошибочно
составлять любую структуру с первой попытки.

### E. Новый тест расширенного требования — отдельный новый чат

Этот запрос новый: он не заменяет и не упрощает исходный ZIP-запрос A.

```text
Создай отдельный проект qa_zip_nested. Загрузи INTERMAGNET IRT и BOU за 2024-09-10 и 2024-09-11. Для каждой из четырёх пар станция-дата построй отдельный HTML-график X и сохрани его в проекте. Имена HTML-файлов пусть выберет код.

Экспортируй проект в qa_zip_nested.zip. Структура внутри ZIP:
папка "Обзор" содержит непосредственно два HTML: IRT за 2024-09-10 и BOU за 2024-09-11;
в этой же папке "Обзор" находится подпапка "Детали";
в "Обзор/Детали" непосредственно лежит HTML BOU за 2024-09-10;
в "Обзор/Детали/Второй день" непосредственно лежит HTML IRT за 2024-09-11.

Не добавляй между указанными папками и файлами каталоги станций и дат. Передай в folders фактические относительные пути HTML из проекта, folder_layout="direct". При совпадении имён файлов пусть код сохранит оба с различимыми именами. Служебные метаданные в корне ZIP допустимы. Перечисли реальные пути четырёх графиков внутри готового архива и предоставь ZIP для скачивания.
```

Критерий: четыре HTML с правильными данными, одновременно файл и подпапка
в `Обзор` и `Обзор/Детали`; пути в ответе совпадают со скачанным ZIP.
Если источник недоступен, не подставлять другую станцию/дату и не считать
полный сценарий пройденным.

## Почему старое падение планнера не равно поломке инструмента

Исходный запрос сохранён в `test_llm_planner_complex_query_real_model`:

```text
Изучи 10 событий (событие01..событие10), для каждого собери данные всех 26 станций и построй графики; объедини всё в архив
```

Прежняя проверка требовала больше 10 шагов и отдельных загрузок/графиков.
Компактный план создания и исполнения матрицы может корректно иметь меньше
шагов. Критерий заменён на структуру матрицы, действия и завершение обработки.
Этот запрос не задаёт даты и состав станций: его нельзя считать научной
приёмкой или исполнять с выдуманными параметрами. Живой тест планирования
остаётся отдельным от офлайн-проверок; здесь он не объявлен пройденным.
