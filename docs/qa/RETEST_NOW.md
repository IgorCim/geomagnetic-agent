# Повторная проверка: только готовые сообщения

Не использовать старую вкладку TOOL_TEMPLATES.md и строки с {…}. Каждая рамка ниже — отдельное сообщение. Номера R — порядок действий, номера инструментов указаны отдельно. Это не список сломанных инструментов: в него включена подготовка. Обязателен журнал вызовов.

После обновления исходников нужен свежий Python-процесс и загрузка модели по Kaggle-инструкции; исходники после загрузки brain не обновлять. 300-chart стресс сейчас не повторять.

## 1. Минимальная подготовка для инструментов и формул

### R01 — создать проект (инструмент 2)

```text
Создай проект qa_acceptance_round3. Укажи фактическое имя и каталог проекта.
```

### R02 — получить таблицы в этот проект (инструмент 3)

```text
В проект qa_acceptance_round3 загрузи IRT и BOU за 2024-09-10 через fetch_many, max_downloads=2. Укажи реальные handle, число строк, сохранённые пути и ошибки.
```

Проверяющий: существуют raw:irt:2024-09-10 и raw:bou:2024-09-10 в этой сессии и station/day CSV в проекте. Если нет — зависимые шаги не запускать.

### R03 — производные IRT (инструмент 8 / A01)

```text
Для raw:irt:2024-09-10 рассчитай H/D/I через calculate_derived_components, без новой загрузки. Укажи формулы, единицы и фактический derived handle.
```

Проверяющий: реальный вызов, H в nT, D/I в deg; atan2, а не arccos. При новой сессии выполнять R01–03 заново. При сохранённой текущей сессии с подтверждёнными таблицами подготовку можно пропустить.

## 4. Короткая проверка исправлений формул

После R02–03, каждый пункт отдельно:

### R11 — night baseline (A03)

```text

```

### R12 — full baseline (A04)

```text
Рассчитай baseline H для derived:irt:2024-09-10, mode=full. Укажи метод.
```

### R13 — цепочка (A06)

```text
Сначала получи calculate_baseline H mode=night для derived:irt:2024-09-10. Затем рассчитай calculate_derived_math metric=anomaly для той же таблицы, передав baseline_value из результата этого вызова, а не по памяти.
```

Проверяющий: оба вызова; anomaly — ряд H-baseline, не поиск 3-sigma выбросов. Baseline берётся из результата именно текущего запроса.

### R14 — прежний ответ без вызова (B05)

```text
Через evaluate_custom_formula вычисли выражение atan2(0,1)+0*X для raw:irt:2024-09-10. Укажи точный новый handle и численный результат инструмента, не заменяй вызов устным расчётом.
```

### R15 — B06


### R16 — B07

```text
Через evaluate_custom_formula вычисли выражение degrees(pi)+0*X для raw:irt:2024-09-10. Укажи точный новый handle и численный результат инструмента, не заменяй вызов устным расчётом.
```

Проверяющий: каждый раз новый вызов, min=max=mean соответственно 0/1/180. Общий slot formula:irt:2024-09-10 может перезаписываться — сохраняйте журнал до следующего шага.

После этого запускать C и новые D/E из FORMULA_RUNBOOK.md небольшими пакетами. C не считать пройденной по правдоподобному тексту. Для положительного substorm нужен SML; для EEJ — обоснованная пара. Ey после исправления нужно перепроверить с текущим OMNI, не сравнивать со старым неверным масштабом как с эталоном.
