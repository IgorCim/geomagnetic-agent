## Одна ячейка для основной и целевой серий

После обновления исходников в свежем kernel и загрузки brain выполнить:

```python
from pathlib import Path
import runpy
import agent_core as ac

assert isinstance(brain, ac.LlamaBrain)
qa_root = Path(ac.__file__).resolve().parent
for qa_ui_name in ('demo', 'qa_download'):
    qa_ui = globals().get(qa_ui_name)
    if qa_ui is not None:
        qa_ui.close()
qa_combined = runpy.run_path(str(qa_root / 'tools/run_combined_acceptance.py'))
qa_result = qa_combined['run'](brain)
print('Результаты:', qa_result['run_dir'])
print('ZIP доказательств:', qa_result['archive'])
```

Исходные промты не заменяются удачными альтернативами. Запускаются обе серии,
каждый независимый чат получает собственное состояние. Восемь сообщений второй
раз отдельно не запускаются: они уже входят в 43. Сохраняются ответы, вызовы,
таблицы и исходный план средствами существующего run_acceptance.
Запись RECORDED не означает PASS. Заблокированная научная подготовка не PASS.

Успех альтернативы доказывает возможность выполнить задачу при этой формулировке,
но не стирает отказ исходного запроса и не доказывает устойчивость к формулировкам.

## Видео Gradio: что не заменяет ячейка

Точные неизменённые промты A–E находятся в
[ORIGINAL_PRODUCT_RETEST.md](ORIGINAL_PRODUCT_RETEST.md).
Для компактного видео сверх объединённой ячейки нужны:

1. A: ZIP с 1/2/3 — показать ответ, скачать именно пользовательский ZIP,
   распаковать, открыть каждый HTML. Дерево проекта и структура ZIP различаются.
2. E: вложенный ZIP — показать все четыре разных пары станция/дата,
   файл рядом с подпапкой, кириллицу и пробел в названии. Проверить содержимое
   графиков, а не только имена файлов.
3. C: подготовка BOU и три последовательных запроса раскладок — показать
   stacked, три HTML, overlay X/Y. Количество файлов не доказывает раскладку.
4. Два браузерных клиента: телефон/компьютер либо два независимых профиля.
   В A выполнить первое сообщение ниже; в B выполнить второе; затем выполнить
   второе в A. B должен отказать, A должен получить статистику без новой загрузки.

Клиент A, подготовка (исходный текст):

```text
Загрузи INTERMAGNET IRT за 2024-09-10 и рассчитай H/D/I. Укажи handle.
```

Клиент B, затем A (исходный текст):

```text
Получи статистику H из derived:irt:2024-09-10. Используй только текущую сессию. Не загружай и не рассчитывай данные. Если таблицы нет, сообщи причину.
```

B (H→Y→X) и D (восстановление) из ORIGINAL_PRODUCT_RETEST тоже можно записать
для демонстрации, но это повтор близких автоматических проверок. Их исходные
формулировки не менять, подготовку не пропускать.

## Хранение и границы доказательств

Присланные журналы скопированы побайтно в локальную папку
`verification/user_logs_20261109`, рядом manifest.json с SHA256.
Это приватная архивная копия; сырые журналы не публикуются автоматически,
поскольку могут содержать пользовательские пути, ссылки и параметры доступа.
Файл 265431d6 смешивает версии: сверять revision для каждого фрагмента.
Файл bcef6649 — завершённая короткая серия на 6fb0eac.
Неполный журнал 43 сообщений не дополняется догадками о завершении.

Для каждого нового видео сохранять HEAD, параметры модели, журнал, скачанный
ZIP и само видео. Скриншот или текст «готово» не заменяет артефакт.

Это не проверка на 100%: остаются научная независимая сверка, недоступные
положительные сценарии источников, конкурентные запросы, частичные матрицы,
таймауты, восстановление после перезапуска и изоляция доступа к файлам.
Часть имеет офлайн-тесты, но их нельзя автоматически объявлять живой приёмкой.
