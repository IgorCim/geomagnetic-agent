# Дополнительные живые проверки

## Как запустить техническую проверку в Kaggle

В отдельной ячейке из папки загруженного проекта:

```python
import subprocess, sys
subprocess.run([sys.executable, '-B', 'tools/verify_offline.py'], check=True)
subprocess.run([sys.executable, '-B', 'tools/verify_gradio.py'], check=True)
```

Это существующие автоматические проверки кода и локального HTTP Gradio с тестовой моделью.
Они не используют Qwen и не означают, что каждый реальный источник сейчас работает.
Результаты сохраняются в verification. Не запускать одновременно с живыми запросами.
Расширенная проверка нагрузки двух живых пользователей остаётся отдельным этапом.

## Диагностика расположения после обновления

Подготовка: успешно загрузить INTERMAGNET BOU за 2024-09-10 в текущем чате.
Сначала повторить обычные запросы ниже. Если модель выбрала неверный режим,
эти точные запросы помогают отделить маршрутизацию от возможностей построителя:

```text
Вызови plot_components для raw:bou:2024-09-10, components=["X","Y","Z"], layout="stacked". Один HTML, три панели сверху вниз, отдельные вертикальные шкалы. Без загрузки данных.
```

```text
Вызови plot_components для raw:bou:2024-09-10, components=["X","Y"], layout="overlay". Один HTML, одна панель, две подписанные кривые на общей шкале nT. Без загрузки данных.
```

Три отдельных HTML требуют трёх вызовов с одной компонентой в каждом. Точный запрос
не заменяет приёмку естественной формулировки. Независимые панели не следует путать
с навигатором времени под графиком.

Статус: подготовлены, не пройдены. Копировать только текст запросов. Сохранять HEAD, журнал вызовов и скачанные файлы. Успешный ответ без нужного вызова не считается успехом.

## ZIP: проверка существующего проекта

Сначала выполнить исходный запрос создания qa_zip_123 и трёх графиков. Затем, если пути в ответе совпадают с указанными ниже, отдельным сообщением:

```text
Экспортируй существующий проект qa_zip_123 в qa_zip_123_verified.zip. Не загружай данные и не строй графики заново. Передай folders={"1":["irt/2024-09-10/X_INTERMAGNET.html"],"2":["irt/2024-09-10/Y_INTERMAGNET.html"],"3":["irt/2024-09-10/Z_INTERMAGNET.html"]}. В папку "1" положи X, в папку "2" — Y, в папку "3" — Z. Не заменяй структуру обычным экспортом. Укажи фактический результат инструмента.
```

Скачать именно этот архив. Распаковать: три пользовательские папки, по одному нужному HTML; служебные файлы допустимы. Открыть каждый HTML. Панель файлов проекта не является списком содержимого ZIP. Этот точный запрос диагностирует экспорт; он не заменяет повтор исходного естественного запроса.

Скачивать архив ответа из «Готовые ZIP выбранного проекта». Кнопка
«Создать отдельный ZIP всего проекта» делает другой, полный архив с обычной
структурой проекта. Она не должна изменять байты ранее созданного архива с
папками пользователя. Это проверяется и автоматически через HTTP.

Офлайн-проверка исключает `live_model`, даже если веса доступны. Найденный в
Kaggle провал `test_llm_planner_complex_query_real_model` не объявлен PASS:
его критерий «больше 10 шагов» не проверяет корректность матричного плана,
а запрос содержит условные события без реальных дат. Переработка научно
определённого живого сценария планировщика остаётся отдельной задачей.

## Восстановление после ошибки: один чат, три сообщения

```text
Загрузи INTERMAGNET IRT за 2024-09-10 и рассчитай H/D/I. Укажи handle.
```

```text
Получи статистику H из raw:zzz:1900-01-01. Не загружай данные и не подставляй другую таблицу. Сообщи причину отказа.
```

```text
Теперь получи статистику H и построй H из derived:irt:2024-09-10. Без повторной загрузки и расчёта H/D/I.
```

Ожидание: отказ только второго сообщения; третье выполняет статистику и построение на сохранённой таблице.

## Контекст компонентов: один новый чат

```text
Загрузи INTERMAGNET BOU за 2024-09-10 и получи статистику H инструментом.
```

```text
Для BOU за 2024-09-10 теперь нужна статистика Y. Используй уже загруженные данные.
```

```text
Из той же таблицы получи минимум, максимум и медиану X инструментом. Не скачивай повторно.
```

Ожидание: H → Y → X, без подмены компонентов и лишней загрузки.

## Расположение графиков: после загрузки BOU

```text
Построй X/Y/Z для BOU за 2024-09-10 как три отдельные панели одна под другой, в одном HTML. У каждой панели своя вертикальная шкала. Используй готовые данные.
```

```text
Теперь построй X/Y/Z из той же таблицы тремя отдельными HTML-файлами, по одной компоненте в каждом.
```

```text
Теперь наложи X и Y из той же таблицы в одной панели на общей шкале nT. Подпиши обе кривые.
```

Оценивать реальное содержимое HTML, а не число ссылок или текст ответа. Возможный отказ от неподдерживаемого расположения фиксировать отдельно от выдуманного успеха.

## Изоляция сессий

В обычном окне загрузить IRT 2024-09-10 и рассчитать H/D/I. В независимом окне инкогнито:

```text
Получи статистику H из derived:irt:2024-09-10. Используй только текущую сессию. Не загружай и не рассчитывай данные. Если таблицы нет, сообщи причину.
```

Ожидание: unknown_frame. В первом окне повторить статистику: должна работать. Очистка через «Новый чат» проверяет сброс, но не одновременную изоляцию.

## Матрицы, сбои, наука и нагрузка

- Частичная матрица: кодом задать успешную, пустую и временно отказавшую ячейки. Проверить отчёт и продолжение без дублирования успешных результатов. Реальную пустоту BOU заранее не предполагать.
- Наука: независимый расчёт из тех же CSV с указанными временем, единицами и обработкой пропусков. Постоянное поле, линейное поле, квадранты D, нерегулярное время, разрывы, непересекающиеся интервалы.
- Источники: кодом воспроизводить таймаут и повреждённый ответ; после отказа выполнять корректную задачу. Честный отказ не считать успешной загрузкой.
- Безопасность: использовать существующие проверки выхода за каталог, опасных выражений, секретов и доступа к файлам другой сессии.
- Нагрузка: существующий стресс дополнять измерением памяти и времени двух сессий; не заменять им скачивание через браузер.
- Устойчивость: для важных задач повторять исходную и уточнённую формулировки в новых чатах и после смены станции. Сравнивать вызовы и файлы; единичный успех не доказывает устойчивость.

Автоматическая ячейка подходит для последовательных диалогов, логов и тестовых сбоев. Она не заменяет проверку реального скачивания, внешнего вида HTML и независимости браузерных сессий.
