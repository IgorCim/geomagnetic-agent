## Последующее исправление

1. Request уже знал запрошенные компоненты, но проверял их только по завершении. Теперь get_statistics с другим либо отсутствующим components отклоняется до обработчика. Разрешены отдельные вызовы для подмножеств явно запрошенного набора: например, сначала Dst, затем Kp. Компоненты сравниваются без учёта регистра.
2. Распознанный набор components явно передаётся в текущем запросе и корректирующем сообщении. Это параметры из вопроса пользователя, не тестовые числа или заранее заданные ответы. Если модель продолжает ошибаться, запрос остаётся неполным; успех не подделывается.
3. Сводка распознаёт также перечисление использованных/подтверждённых данных разговора, включая реальную последнюю формулировку из LONG_CHAT.md. Перечисление внешнего каталога не перехватывается. Сводка состояния строится без модели; журнал её вызовов может быть пустым, поскольку вызова модели нет.
4. Идентичная повторная статистика одной таблицы печатается один раз; полный журнал вызовов сохраняет все попытки.

SYSTEM_PROMPT, загрузчики, физические формулы и код agent_core.py в этом последующем исправлении не менялись. Изменены chat_session.py и подключение распознавания сводки в Gradio.

Сначала воспроизведены семь новых отказов тестов и два контрольных PASS. Затем добавлены отрицательные контроли каталога и проверка отсутствия дубликатов. Итог: **1054 passed, 1 skipped, 22 deselected, 63.41 s**, verification/20261103T061140Z; HTTP семь групп PASS, verification/20261103T061151Z_gradio. Тестовая модель намеренно вызывает неправильные компоненты перед правильными; это не новый запуск Qwen. Живой статус следующего исправления — LIVE_PENDING.

## Следующая проверка

Полный 300-chart stress и весь длинный диалог повторять для этих двух мест не требуется. После публикации и CI — свежий kernel, актуальные ячейки 1–6, затем 8. Сохранённые веса и результаты не удалять.

В новом Gradio-диалоге: загрузить BOU за 2024-09-10 и рассчитать H/D/I; затем отдельно запросить статистику X, Y, Z и F из этого набора без повторной загрузки; последним сообщением отправить «Кратко перечисли станции, даты и результаты, которые можешь подтвердить доступным контекстом и инструментами. Не восстанавливай забытые числа по догадке; явно укажи пробелы». Сверить components в журнале каждого статистического ответа. В ответах должны быть именно запрошенные компоненты, без «запрос выполнен не полностью»; сводка должна ссылаться на реальные таблицы BOU и не придумывать BOX. Числа нужно сверять с инструментом, не с прежним свободным ответом модели.
