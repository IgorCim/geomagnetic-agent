# Kaggle: запуск из GitHub

Используйте обновлённый kaggle_portfolio_acceptance.ipynb в свежем kernel, ячейки по порядку. **Dataset/Input и загрузка ZIP не нужны.** Источник кода — master репозитория https://github.com/IgorCim/geomagnetic-agent.git.

Предложенная ранее схема с source ZIP не соответствовала исходному GitHub-процессу проекта. Она заменена. Архивы 20261101/20261102 остаются историческими снимками; загружать их в Kaggle для текущего запуска не нужно.

## Новая первая ячейка

1. До сетевых действий проверяет, что модули агента и brain ещё не загружены. При необходимости перезапустите kernel; файлы удалять не требуется.
2. Скачивает master в новую папку с автоматически выбранным именем geomagnetic_github_*. Существующие папки, проекты, веса и результаты сохраняются.
3. Проверяет наличие актуального протокола и тестовых файлов, печатает полный HEAD, создаёт SOURCE_MANIFEST.json с SHA-256 отслеживаемых файлов.
4. Подключает прежние GGUF из старой папки models, если они есть. Для новых весов использует отдельную geomagnetic-models, не зависящую от папки checkout.

До загрузки модели повторять первую ячейку можно: новое имя создаётся автоматически. После загрузки модели код не обновлять. Для другой версии — свежий kernel. Manifest создаёт сама ячейка, искать его в /kaggle/input больше не требуется.

## Соответствие прежним ячейкам

| Прежняя ячейка | Новый порядок |
|---|---|
| SUPERMAG_LOGON в os.environ | Ячейка 4 сохраняет уже заданное значение или читает Kaggle Secret. Значение не печатает |
| Проверка imports перед pip | Ячейка 2 ставит зависимости проекта и CUDA wheel, проверяет GPU/offload. Сам успешный import не доказывает GPU |
| Отключение C++ logger | Для первого приёмочного запуска оставить логи: они нужны для ошибок загрузки и подтверждения offload |

## Порядок проверки

Ячейки 1–6: GitHub → зависимости → offline/HTTP-регрессии → SuperMAG → настоящая модель → короткий live preflight. Затем ячейка 8, диалог P1/P2 и [20 ходов](LONG_CHAT.md). До исходной проверки контекста системный промпт не сокращать.

Полный stress — ячейка 7. При отказе SuperMAG сохранить реальный FAIL; затем можно независимо проверять Gradio через ячейку 8. Это не превращает six-source gate в PASS. Ячейка 9 сохраняет доказательства и ссылки скачивания. После аварии stress путь экспорта восстанавливается, временные таблицы освобождаются.

В Kaggle для доступа из браузера пользователя ячейка 8 теперь включает PUBLIC_DEMO=True и inline=False. Открывайте напечатанную публичную ссылку в отдельной вкладке, а не 127.0.0.1. Встроенной авторизации нет; после демонстрации закрыть сервер. При повторе уже установленный CUDA wheel не скачивается; загрузка модели использует тихий режим.

Служебная логика notebook проверяется python -B tools/verify_notebook.py: локальный Git-репозиторий вместо сети, два последовательных checkout, сохранение прежних весов/файлов, запрет смешивания загруженного kernel, env/Secret и cleanup при success/failure stress. Это не заменяет live Qwen/CUDA-приёмку.
