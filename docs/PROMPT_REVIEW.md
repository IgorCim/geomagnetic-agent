# Разбор системного промпта — 02.11.2026

Production-промпт и router в этой работе не изменялись. Нет live A/B на Qwen, поэтому улучшение качества или скорости от сокращения не заявляется.

## Измеренный размер

Отчёт: `verification/20261102_prompt_review/budget.json`. Использована существующая эвристика `estimate_tokens`, не настоящий tokenizer GGUF.

| Вход | Оценка токенов |
|---|---:|
| SYSTEM_PROMPT, 3194 символа | 885 |
| Он же + все 29 схем | 8187 |
| Запрос IRT → H/D/I → график, 4 выбранные схемы | 1858 |
| Продолжение «построй D из тех же данных», 4 схемы | 1858 |
| SuperMAG indices, 1 схема | 1167 |
| Пакетная матрица, 6 схем | 2822 |

Это только system + schemas: сюда не входят user query, история, scratchpad, результаты инструментов, chat template и ответ. Контекст по умолчанию 16384. Оценка полного каталога близка к порогу существующего теста 8192; это не означает переполнения обычного запроса с выбором четырёх схем. Главный объём worst case создают схемы, а не 885 токенов основы.

`build_dynamic_prompt` вопреки своей docstring добавляет к **полному** base_prompt описания выбранных tools и context; не вырезает ненужные разделы. При обычном run_agent system message пересобирается с актуальным scratchpad на каждом ходе: текст не должен накапливаться бесконечно. Tool history ограничивается отдельно.

## Что нужно сохранить

Запрет выдумывать цифры, использование инструментов, точные frame_handle, разные handle для разных дней, обработку ошибок, формат tool_call, различие H/D/I и статистики, обязательный baseline_value, solar_wind_handle и правила матрицы. За этими инструкциями стоят реальные регрессии; удаление по принципу «кажется лишним» не является безопасной оптимизацией.

## Кандидаты для отдельного A/B

1. Общий раздел ИНСТРУМЕНТЫ повторяет имена из переданных схем и перечисляет недоступные текущему запросу инструменты. Можно пробовать заменить его указанием пользоваться только текущими схемами. Это уменьшит текст, но эффект на поведение надо измерить.
2. SSC, пакетный алгоритм и источники можно добавлять по intent вместо глобальной вставки. Однако нельзя решать только по буквальному слову: нужны тесты русских перефразировок, продолжения чата и задач с несколькими источниками.
3. «ПЕРЕД ЛЮБЫМ графиком — fetch» конфликтует с повторным использованием уже загруженного frame. Нужна формулировка «используй имеющийся подходящий handle, загружай при отсутствии». Это изменение поведения, не косметическое удаление.
4. «После матрицы НЕ вызывай никаких инструментов» может противоречить задаче, где после матрицы ещё нужны NOAA/SuperMAG или пользовательский экспорт. Ограничение должно относиться к завершённой подзадаче, а не автоматически ко всему запросу.
5. Фиксированный пример raw:irt:2024-09-12 способен отвлекать от реальной даты; его стоит заменить нейтральным правилом после проверки регрессий.
6. Утверждение об официальной декомиссии ISWA сильнее имеющихся доказательств. При следующей правке отделить недоступность текущей legacy-интеграции от решения NASA. Индексы SuperMAG не эквивалентная замена пространственной карте.

## Как принять изменение

Сначала сохранить baseline: P1–P6/E1–E6 и 20-ходовую проверку с настоящей Qwen. Затем один небольшой вариант промпта, прежние код/модель/данные/параметры. Проверять tool selection и успешные операции, station/date/handle, отсутствие повторного fetch без причины, завершение матрицы, ошибки, правильность чисел и единиц, TTFT/total time, prompt/completion tokens. Для неоднозначных задач повторить одинаковые прогоны; один удачный ответ не даёт уверенности.

Форматные unit-тесты и существующие offline регрессии обязательны, но не заменяют этот live A/B. При ухудшении любого обязательного сценария кандидат отклоняется. До измерений разумнее оставить текущую основу, чем сокращать её ради небольшой экономии токенов.
