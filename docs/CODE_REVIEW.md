## Подтверждённые исправления интерфейса в этой работе

Новые `test_gradio_acceptance.py` сначала дали четыре отказа:

1. `ok=False` с уже готовым графиком обрабатывался ранним выходом: график и исходная сводка терялись.
2. Более 12 графиков обрезались вместе со списком файлов, хотя 12 — только число мест для превью.
3. Матричный результат возвращал matrix_path, а интерфейс не извлекал его готовые графики.
4. Запасной FrameStore без явного Workspace разделял указатель активного проекта с глобальным объектом.

Теперь сохраняются частичные результаты/журнал, все downloads доступны, превью ограничены 12 с явной подписью. Для матрицы извлекаются только успешные station/day ячейки внутри её собственного разрешённого проекта; старый график провалившегося дня не выдаётся за успешный новый результат. Создание UI-сессии использует отдельный Workspace.

Маскирование `logon` в SuperMAG URL добавлено для диагностических логов и error detail: до этого HTTP-ошибка могла показать значение из URL при записи экрана. Это не ремонт legacy API.

## Найденные ограничения вычислений — не скрывать

### Ey: масштаб и подпись

`physics_engine.calculate_coupling_function` сейчас вычисляет V×Bz и подписывает результат mV/m. Для V в km/s и B в nT перевод величины в mV/m требует множителя 10⁻³: 400 km/s × 5 nT соответствует 2 mV/m по модулю, а не 2000. В коде и существующих тестах сохранено ожидание ±2000. Знак также является явно выбранной автором конвенцией V×Bz, а не автоматически обычным −V×Bz.

Это подтверждённое размерностное расхождение. Старый зелёный тест здесь закрепляет реализацию, а не независимую физическую истину. Формула не исправлялась в рамках ремонта Gradio. **Ey нельзя показывать как научно проверенный результат до отдельной коррекции кода, тестов, подписей и проверки влияния на связанные сценарии.**

### Временное разрешение

GIC-прокси и peak_dhdt используют разности соседних samples; peak window фактически задан числом samples, хотя часть названий/notes говорит «секунды». Некоторые пути предполагают минутный регулярный ряд. SSC нормализует скорость по timestamp отдельно; это не делает остальные функции универсальными для секундной/неравномерной сетки. В `geomag_math.calculate_dH_dt` параметр samples_per_minute делит разность, поэтому для режима, отличного от 1, нужно отдельно проверить смысл и масштаб.

### Dst, Sq, Burton, EEJ и координаты

- Dst-proxy одной станции с ночной базовой линией не является официальным Dst. В обработчик latitude не передаётся; default 0. Текущая формула с cos(latitude) — выбранная упрощённая реализация, не аттестованная методика восстановления глобального индекса.
- Legacy `geomag_math.calculate_dst_proxy` фактически выдаёт вторую разность; его комментарий о происхождении Dst научно некорректен. Основной dispatch `apply_physics_formula(metric='dst_proxy')` использует другую функцию из physics_engine, поэтому наличие двух функций важно объяснять.
- «Sq» — постоянная ночная медиана компонентов одного окна, а не полноценная суточная Sq-модель по ансамблю спокойных дней.
- Burton здесь — упрощённый одночасовой шаг по усреднённым входам, не полноценная проверенная модель прогноза Dst. Выбор уже загруженного индекса не гарантирует совпадение его окна с запросом.
- EEJ вычитает ряды одинаковой длины; совпадение timestamp и геофизическая пригодность пары станций требуют отдельной проверки. IRT в примере схемы не следует представлять как реальную экваториальную станцию.
- Координаты — наклонный диполь с фиксированным полюсом, не IGRF/AACGM. MLT приближённый; округление минут на границе часа требует отдельной регрессии.
- SSC — кандидаты по наземному импульсу; подтверждение требует независимого солнечного/сетевого контекста. Сигма-аномалия не равна физической буре.

### Метаданные и долговечность

INTERMAGNET записывает `publication_states`, а часть потребителей ждёт единственный `publication_state`; manifest может честно содержать null. Кэш возвращает часть provenance через вложенный cache_meta; полная идентичность attrs свежей загрузке не гарантирована. При CSV fallback запись меняет расширение, а чтение сначала ищет Parquet-путь. Поэтому нельзя обещать полную воспроизводимость provenance только по manifest.

CSV/JSON/ZIP и матрицы записываются без транзакционной БД и общей защиты от конкурентной перезаписи. Имена файлов могут совпасть у разных пользователей. Путевая защита тестируется, но приложение в целом не прошло аудит безопасности публичного SaaS.

## Что означает успешный тест

Офлайн-suite проверяет контракты, парсер, математику на заданных примерах, обработку ошибок, структуру артефактов и сценарии с doubles. Часть тестов близко повторяет формулу реализации. Пример Ey показывает, почему прохождение suite не равно научной аттестации.

Для публичного видео основного MVP достаточно отдельно подтвердить live-путь данных/графиков/проектов/ошибок и честно вынести экспериментальную физику в ограничения. Для заявлений «научно корректны все метрики» перечисленные вопросы являются блокирующими. Для SaaS дополнительно блокируют отсутствие auth/tenant storage/durable jobs/лимитов памяти и недоказанное поведение длинного диалога с настоящей моделью.
