## Дополнительные промпты анализа

После P1 используйте фактический handle из ответа; не угадывайте его при отличающемся имени.

### A1. Статистические выбросы

```text
Для derived:irt:2024-09-10 выполни detect_anomalies по H с sigma_threshold=3. Покажи число отмеченных отсчётов и порог. Объясни, что это статистические выбросы выбранного ряда, а не подтверждённые физические события.
```

### A2. Baseline и производные

Лучше отправлять последовательно, сохраняя реальный численный baseline из первого ответа.

```text
Для derived:irt:2024-09-10 вычисли calculate_baseline по H, mode=night, night_hours=[0,4]. Укажи baseline и что окно задано в UTC.
```

```text
Для той же таблицы вычисли calculate_derived_math: сначала metric=delta по H без окон, затем metric=dH_dt. Назови единицы и шаг временной сетки. Не называй window_seconds физическими секундами без проверки реализации.
```

```text
Вычисли calculate_derived_math с metric=anomaly по H, используя точное baseline_value из инструмента первого шага. Построй результат и назови новый handle. Если число baseline недоступно в контексте, запроси его заново, не угадывай.
```

### A3. Сохранённая работа

```text
Выполни list_projects. Для portfolio_irt_bou_20261101 перечисли фактически сохранённые станции, даты и графики. Не утверждай, что таблицы переживут перезапуск RAM-сессии, только потому что CSV есть на диске.
```

## Научная приёмка: отдельный обязательный этап

Пока не завершена. Известные проблемы описаны в [CODE_REVIEW.md](CODE_REVIEW.md). Нельзя превращать проверку вызова инструмента в подтверждение физической правильности.

Для sq_baseline, deltas, gic, dst_proxy, ey_coupling, ssc_flag, burton_coupling, akasofu_epsilon, peak_dhdt, substorm_onset и eej_index нужны независимые расчёты с явно заданной конвенцией и допуском. Фикстуры: постоянный ряд, линейный рост, импульс, NaN/пустой ряд, минутная/секундная/нерегулярная сетка, разные timestamps двух станций. Отдельно проверять единицы, знак, sampling и отсутствие выдуманных выводов модели.

Контроль Ey: V=400 km/s, |Bz|=5 nT → |Ey|=2 mV/m. Сейчас функция возвращает масштаб 2000 с подписью mV/m; этот gate заведомо не пройден. Dst proxy не сравнивать с официальным Dst как тождественную величину. EEJ требует физически обоснованной пары экваториальной/референсной станций; наличие двух рядов одинаковой длины не подтверждает их временное совпадение.

## Сквозные требования сверх 29 имён

- Длинный диалог: [20 ходов Qwen](LONG_CHAT.md), независимая сессия B, ошибка → восстановление.
- Интерфейс: кнопка/Shift+Enter, очередь и повторная отправка, >12 графиков, пустой проект, partial, downloads/ZIP. Текущий browser-тест не доказывает работу всех мобильных экранов или всех браузеров.
- Нагрузка: сначала 50, затем staged 300; измерить wall time, RAM/VRAM, объём файлов и очистку. Параллельных пользователей и длительный soak-тест пока не считать пройденными.
- Числа/артефакты: для заявления о всех 300 сверить все Plotly traces с соответствующими CSV, не только имена и число HTML. Текущий stress_300 не делает полной численной сверки.
- Отказы поставщиков: timeout, no_data, invalid station, missing credentials и реальный 404 отражаются раздельно. Ожидаемый корректно показанный отказ не равен доступности данных.
- SaaS: авторизация, tenant isolation файлов/секретов, квоты, durable jobs и восстановление после перезапуска — отдельные непройденные требования платформы.

Условия выпуска для портфолио: пройдены заявляемые пользовательские сценарии на настоящей модели; ограничения явно подписаны; сохранены доказательства. Условия выпуска как научного SaaS существенно шире и сейчас не выполнены.
