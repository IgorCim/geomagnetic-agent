## Что исправляется в коде, а что в инструкции

Код: сохранять в журнале компактные фактические поля вычислений; требовать успешный решающий вызов для запроса вычислить; собирать численный итог из результата инструмента; проверять текущую metric, formula, baseline mode/window и передачу baseline между двумя шагами. Концептуальное объяснение инструмента не требует его запуска. Новые правила проверяются ScriptBrain, который сначала/в конце выдаёт намеренно ложные числа.

Router: явно названный зарегистрированный инструмент не должен теряться внутри составного запроса; anomaly subtraction и statistical outlier detection разведены. Это общие контракты, не отдельные if для IRT/конкретных дат/контрольных чисел.

Инструкция: никаких незаполненных полей в ручном пакете; подготовка таблиц в текущей сессии; для substorm нужен SML, для EEJ — обоснованная пара. Не меняем корректные исходные запросы A04/A06/B05–07 ради зелёного результата.

Научная правка Ey следует [первичному определению NASA OMNI](https://omniweb.gsfc.nasa.gov/html/ow_min_data.html): V в km/s, Bz GSM в nT, Ey=-V*Bz*10^-3 mV/m. Контроль 400/-5→+2, векторные значения и знак проверяются независимыми числами. Это не означает завершения научного аудита остальных метрик.

## ZIP

Раздел «Проекты и скачивание ZIP» теперь открыт по умолчанию. Кнопка собирает стандартный архив. Отдельный список «Готовые ZIP выбранного проекта» показывает в том числе созданные агентом custom ZIP. Список проверяет project в export_manifest.json, не распаковывает архивы и не доверяет путям из metadata. Повреждённые, чужие и слишком большие manifest пропускаются.

Проверять стандартный и пользовательский ZIP отдельно: HTTP 200, zipfile.testzip(), наличие ожидаемых каталогов/файлов. Локальная детерминированная HTTP-проверка не заменяет реальный большой download через Kaggle.

## Что запускать пользователю

Один текущий документ — [RETEST_NOW.md](qa/RETEST_NOW.md). В нём буквальные имена/handle и подготовка, без {…}. Расширенная [линейка формул](qa/FORMULA_RUNBOOK.md) теперь содержит готовые D (преобразования) и E (отказы/восстановление); F обозначает проверки, требующие синтетических code fixtures.

SYSTEM_PROMPT не изменять ради этих случаев. Архитектура LLM tool calls сохраняется: модель по-прежнему выбирает/вызывает расчёты, но отсутствие вызова или его фактический результат нельзя заменить убедительным ответом.
