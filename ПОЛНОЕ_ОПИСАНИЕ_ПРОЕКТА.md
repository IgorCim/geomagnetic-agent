# ЧАСТЬ I. ЧТО ЭТО ТАКОЕ (для серьёзных людей)

**Геомагнитный ИИ-агент** — локальная научная система, которая:

1. **Скачивает** реальные геомагнитные данные из 6 международных источников (INTERMAGNET, NASA CDAWeb/OMNI, SuperMAG, NOAA SWPC, NASA ISWA, Kyoto WDC).
2. **Считает** по ним физику и математику — H/D/I/F, дельты, производные, GIC-прокси, Dst-прокси, Бёртона, Акасофу, EEJ, SSC, начало суббури и др.
3. **Строит** интерактивные графики — в том числе **несколько линий на одном графике**, **несколько графиков сразу**, **до 12 в панели** и **сотни пакетно**.
4. **Планирует и выполняет массовые задачи** — «26 станций × 10 событий» превращает в матрицу и прогоняет её без участия модели.
5. **Хранит результаты в проектах** с манифестами (что, откуда, когда, каким коммитом) и **упаковывает в ZIP**.
6. **Отвечает по-русски**, кратко, только реальными числами из инструментов.

**Ключевая инженерная идея:** маленькая локальная модель (7B) не должна помнить много и не должна выдумывать. Память вынесена в `Scratchpad`, вся физика — в **один** мета-инструмент, объём работы — в **матрицу**, научная честность — в контракт ошибок и манифесты.

**Без платных API и ключей:** веса один раз скачиваются из HuggingFace, дальше всё работает внутри процесса. Логин нужен только для SuperMAG (бесплатная регистрация).

# ЧАСТЬ III. ВСЕ 29 ИНСТРУМЕНТОВ (полный реестр)

> Схемы — в `TOOL_SCHEMAS`; ровно 29 имён = 29 хендлеров (`HANDLERS`); расхождений нет (проверено).

### III.1. Данные (8)
1. **`fetch_observatory_data`** — день одной обсерватории. `station_code`, `start_date`, `end_date`, `data_type` (`definitive|quasi-def|adjusted|reported|best-avail|auto`), `samples_per_day` (`Minute|Second`). → `raw:<ST>:<date>`.

4. **`fetch_geomagnetic_indices`** — Dst (часовой) + Kp (3-часовой) из Kyoto → `idx:kyoto:<date>`.
5. **`fetch_supermag_data`** — SuperMAG: `data_type='sites'` (нужна станция) / `'indices'` (SME/SML/SMU). Лимит 32 дня. → `idx:supermag:<date>`.

8. **`get_iswa_perturbation_map`** — карта возмущений ISWA. **⚠️ ДЕКОМИССИРОВАНА** → вернёт `service_decommissioned` + план замены.

### III.2. Физика и математика (8)
9. **`apply_physics_formula`** — **ЕДИНЫЙ мета-инструмент всей физики.** `df_descriptor`, `metric` (11 значений), `external_params`, `window_seconds`, опц. `solar_wind`/`solar_wind_handle`.

11. **`calculate_derived_components`** — производные H/D/I из X/Y/Z. `df`, `components[]`.
12. **`calculate_derived_math`** — скалярные метрики: `delta`, `anomaly`, `dH_dt`. `df`, `metric`, `component`, `window`, `baseline_value`.
13. **`calculate_baseline`** — тихий опорный уровень. `df`, `component`, `mode` (`night|full`), `night_hours[]` → отдаёт `baseline`, который потом идёт в `calculate_derived_math`.

16. **`detect_anomalies`** — выбросы по сигмам. `df`, `component`, `threshold` (по умолчанию 3σ).

# ЧАСТЬ IV. ФОРМУЛЫ — ТРИ УРОВНЯ (это ядро научной части)

Формул действительно **много**, и они не в одном месте. Три уровня:

| Уровень | Модуль | Что считает |
|---------|--------|-------------|
| **А. Базовая математика** | `geomag_math.py` | компоненты, вариации, производные, базис, DSL |
| **Б. Физика** | `physics_engine.py` | 11 физических метрик через `apply_physics_formula` |
| **В. Анализ и координаты** | `geomag_analyzer.py`, `geomag_coords.py` | статистика, аномалии, производные, координаты, MLT |

## IV.А. Базовые формулы (`geomag_math.py`, 986 строк)

- **H (горизонтальная):** `H = hypot(X, Y)`.
- **F (полное поле):** `F = hypot(hypot(X,Y), Z) = sqrt(X²+Y²+Z²)`, всегда `F ≥ H`.
- **D (склонение):** `D = degrees(arctan2(Y, X))` ∈ [−180°, 180°], на восток положительно; при X=Y=0 → 0.0.
- **I (наклонение):** `I = degrees(arctan2(Z, H))` ∈ [−90°, 90°], вниз положительно; при H=0 → ±90°.
- **Дельта:** `max − min` по всему фрейму либо по блокам `window=N`.
- **Аномалия:** `B − baseline_value`; при `baseline_value=None` — намеренная ошибка `missing_baseline`.
- **dH/dt:** первая разность `B[i]−B[i−1]`, нТл/мин; `samples_per_minute` масштабирует субминутные данные.
- **d²H/dt²** (`calculate_dst_proxy` базовый): вторая производная — кривизна поля.
- **Ночной базис** (`get_nighttime_baseline`): среднее за 00:00–04:00 UT; окно замкнутое, поддержан переход через полночь `(22,6)`; `baseline=None` при пустом окне (не NaN).

**Безопасный DSL формул** (`evaluate_formula`):
- **Операторы:** `+ − * / % **`, унарные `+ −`.
- **19 функций:** `sqrt, sin, cos, tan, asin, acos, atan, atan2, abs, exp, log, log10, hypot, degrees, radians, power, minimum, maximum, sign`.
- **Константы:** `pi`, `e`, `nan`.
- **Колонки:** собственные числовые + производные `H/F/D/I` + `X/Y/Z`.
- **Безопасность:** AST-whitelist — разрешены только `Expression, BinOp, UnaryOp, Call, Constant, Load, Name`. **Нет** `Attribute` (нет `os.system`), `Subscript` (нет `X['__class__']`), `Lambda`, `Compare`, `IfExp`, `Dict/List/Set`. Формула **парсится, но никогда не исполняется как код.**

## IV.Б. 11 физических метрик (`physics_engine.py`, 1274 строки)

Доступны через `apply_physics_formula` (+ алиас `dH_dt` → `gic`).

**1. `sq_baseline` → `extract_sq_baseline`.** Тихий уровень Sq. Медиана (по умолчанию) X/Y/Z за 00:00–04:00 UT. Выход: `X_sq/Y_sq/Z_sq/H_sq/F_sq`. Почему медиана, а не среднее: ночное окно в основном тихое, но содержит редкие всплески (суббуря, сбой); среднее тянется к каждому всплеску, медиана — нет.

**2. `deltas` → `calculate_deltas`.** Отклонение от Sq: `dX = X − X_sq`; `dH = hypot(dX, dY)`; `F_delta = hypot(dH, dZ)`. Выход: `dX/dY/dZ/dH/F_delta`.

**3. `gic` / `dH_dt` → `calculate_gic_proxy`.** Стандартный прокси GIC — `dH/dt` (нТл/мин). Выход: `dH_dt` + `attrs['dH_dt_peak_abs_nT_per_min']`.

**4. `dst_proxy` → `calculate_dst_proxy`.** Упрощённый Dst: `dH = H − H_sq`; `dst_proxy = dH · cos(широта)`. Отрицателен при буре.

**5. `detect_ssc` → `detect_ssc`.** Внезапное начало по `dH/dt > 5 нТл/мин`. Выход: `ssc_flag`, `dH_dt`, `attrs['ssc_events']` (до 10).

**6. `ey_coupling` → `calculate_coupling_function`.** `E_y = V · B_z` (мВ/м при V км/с, Bz нТл). Скаляры → константа; вектора (из `align_solar_wind`) → колонка `E_y`.

**7. `burton_coupling` → `calculate_burton_coupling`.** Модель кольцевого тока Burton et al. (1975):
```
dDst/dt = a · sqrt(Np) · V · Bs − Dst/τ
Bs = −Bz (Bz<0, иначе 0);  a = 0.005,  τ = 8 ч
```
Одношаговый (1 ч) прогноз Dst.

**8. `akasofu_epsilon` → `calculate_akasofu_epsilon`.** Энерговклад солнечного ветра:
```
ε = V · B_total² · l0² · sin⁴(θ/2)
B_total = sqrt(Bx²+By²+Bz²);  θ = arctan(By/Bz);  l0 = 7 RE
```
Отдаёт и ватты, и эрг/с.

**9. `peak_dhdt` → `calculate_peak_dhdt`.** Пиковое `|dH/dt|` в скользящем окне (`window_seconds`, по умолчанию 10). Уровни: `low`<50, `medium`≤200, `high`>200 нТл/мин.

**10. `substorm_onset` → `detect_substorm_onset`.** Первый сэмпл устойчивого падения SML: `dSML/dt < −50 нТл/мин` держится ≥3 мин. Выход: `onset_time`, `sml_drop`, `confidence`.

**11. `eej_index` → `calculate_eej_index`.** `EEJ = H(экватор) − H(референс)`; референс в 6–8° по широте.

**Плюс вспомогательная** `align_solar_wind` — выравнивает солнечный ветер по минутной сетке обсерватории (лаг в минутах, линейная интерполяция с `limit`, не экстраполирует за края).

**⚠️ Коллизия имени `dst_proxy`:** в проекте ДВЕ функции с этим именем — базовая (2-я производная d²H/dt²) и физическая (`dH·cos широты`). Через инструменты доступна только физическая.

### Технические тонкости
- Выход: `DEFAULT_OUTPUT_DIR = <модуль>/plots`; `fig.write_html(..., full_html=True, config={displaylogo:False, scrollZoom:True, toImageButtonOptions:{format:'png', scale:2}})`, возвращает **абсолютный путь**.

- В Gradio график инлайнится через **`<iframe srcdoc>`** (не `innerHTML` — тот не исполняет `<script>`); payload экранируется `html.escape(quote=True)`.
- Восстановление фигуры из HTML (`_figure_from_html`) распознаёт `Plotly.newPlot/newPlot2/react/animate/restyle`.

# ЧАСТЬ VI. ПРОЕКТЫ, МАНИФЕСТЫ И ZIP

**Раскладка** (`project_store.py`, 610 строк):
```
projects/<name>/
    manifest.json
    <station>/<date>/
        manifest.json
        raw.csv  derived.csv  *.html
```
Корни: `PROJECTS_ROOT = <модуль>/projects`, `EXPORTS_ROOT = <модуль>/exports`.

**Почему дерево, а не файлы в куче:** станция и дата — это папки, поэтому сравнение = glob, два прогона не сталкиваются, а ZIP понятен тому, кто откроет.

**Манифест проекта:** `{project, stations, dates, artifacts, created_at, updated_at, agent_commit}`.
**Манифест листа:** `{project, station, date, kind, file, rows, columns, data_version, source, downloaded_at, agent_commit, geomagnetic_coords, written_at}` — четыре вопроса, которые задают к результату через год: откуда, definitive ли, когда скачано, каким коммитом.

**Безопасность имён:** `_slug` отбрасывает `../..` и абсолютные пути (имя приходит от модели как недоверенный ввод); дополнительно проверяется, что путь — прямой потомок корня.

**ZIP (`export_project`):** обновляет манифест по диску, затем `zipfile.ZipFile(..., ZIP_DEFLATED)` — **перезаписывает, а не досыпает**. Пишет в `exports/<name>.zip`. Возвращает `{ok, project, path, bytes, size, files, stations, dates, manifest}`.

**Ошибки хранилища:** `invalid_project_name`, `project_not_found`, `unreadable_manifest`, `invalid_artifact_path`, `artifact_write_failed`. При отсутствии проекта `project_tree`/`list_projects`/`iter_manifests` возвращают **пустую коллекцию**, не ошибку.

**`agent_commit()`** — git HEAD через subprocess, кэшируется: числа воспроизводимы только с тем кодом, что их сделал.

# ЧАСТЬ VII. МАССОВАЯ ОБРАБОТКА (матрица) — «200 графиков»

**`create_task_matrix`** планирует большую задачу как **ОДНУ матрицу, сгруппированную ПО СТАНЦИЯМ**: одна задача на станцию со всеми её датами. Порог `MATRIX_THRESHOLD = 15` юнитов; задача 10×26 → матрица из 26 задач (станция×событие **никогда не перечисляется**).

**Слова-действия** (`MATRIX_ACTION_ALIASES`): `fetch`, `calc_hdi`/`hdi`/`derive`, `plot`, `stats`, `anomalies` (+ полные имена хендлеров).

**`process_matrix_batch`:** `run_until_complete=True` — обрабатывает **ВСЕ** станции за один вызов и **сам вызывает `_handle_export_project`** (потому что после тяжёлого прогона 7B-модель надёжно забывает шаг экспорта). Сводка начинается с **«МАССОВАЯ ОБРАБОТКА ЗАВЕРШЕНА»**.

**`fetch_many` внутри:** бюджет `MAX_BATCH_DOWNLOADS = 8` — **один потолок на весь вызов**; `spent` растёт **до** запроса (зависший запрос тоже ест бюджет); упавшая станция → в `failed`, цикл `continue`.

**Короткое замыкание:** если `process_matrix_batch` вернул `completed_run=True`, длинный payload **не отдаётся модели** (переполняет контекст 7B → пустой ответ) — цикл сразу возвращает `stop_reason="matrix_completed_short_circuit"`.

**Правило для модели:** НИКОГДА не вызывать `process_matrix_batch` в цикле, НИКОГДА не вызывать `create_task_matrix` повторно.

# ЧАСТЬ VIII. «МОЗГ»: ЦИКЛ, ПАМЯТЬ, САМООБУЧЕНИЕ

## VIII.1. Почему tool-calls парсятся из ТЕКСТА
`llama-cpp-python` рендерит схемы в промпт, но его Jinja2-путь (`_convert_text_completion_to_chat`) заполняет только `content` — `tool_calls` не появляется. Qwen печатает литеральный блок `<tool_call>{...}</tool_call>` **внутри текста**. Цикл, который проверяет `message["tool_calls"]`, не сработал бы никогда. Поэтому `parse_tool_calls()` — **сердце модуля**: он терпим к обёрткам, кривым кавычкам (`_straighten_quotes`, `_single_quotes_to_double`) и вытаскивает JSON-объекты даже из грязного текста.

## VIII.2. `Scratchpad` — внешняя рабочая память (самокоррекция и самообучение)
Обычный Python-объект, а не контекст модели:
- `current_handle` — активный frame_handle;
- `completed_steps` — что уже сделано (без повторов);
- `errors` — история ошибок с подсказками (последние 3 идут в промпт);
- `plan` — план;
- `failed_calls` — `(tool, signature, error)`, обрезается до `LOOP_WINDOW=8`.

`to_prompt_injection()` рендерит **ровно нужные сейчас факты**, одной короткой строкой. Если одна и та же пара (инструмент+аргументы) упала `LOOP_THRESHOLD=3` раза подряд — генерируется **`[CRITICAL LOOP DETECTED]`** с конкретным исправлением: модель обязана сменить стратегию. `_next_step()` подсказывает следующий шаг из состояния. Это и есть **лёгкое самообучение в рамках запроса** — система помнит свои ошибки и не повторяет их.

## VIII.3. Цикл `run_agent` (18 раундов / 16 вызовов)
```
round = 0
while round < MAX_ROUNDS(18) and spent < MAX_TOOL_CALLS(16):
    1. brain.chat(messages, tools) → текст + список вызовов
    2. нет вызовов          → стоп (stop_reason="no_tool_calls") → финальный текст
    3. бюджет исчерпан      → refused-записи, форсируем ответ
    4. для каждого вызова:
         malformed → malformed_tool_call + образец синтаксиса
         unknown   → unknown_tool + _self_correction_hint
         известный → HANDLER(args, store) → payload, note
         исключение → tool_exception (traceback в stderr, цикл жив)
    5. payload → _compact_tool_message (≤400 символов) → роль "tool"
    6. обновить Scratchpad
```

## VIII.4. Валидация до исполнения
- **`_strict_argument_check`** — allow-list: лишний ключ → `unknown_arguments` со списком **допустимых** ключей (единственная подсказка, которая чинит вызов).
- **`_validate_external_params`** — до диспетчеризации проверяет, что для `burton_coupling` есть `Np/V/Bz/Dst`, для `akasofu_epsilon` — `V/Bx/By/Bz`; отсутствие называется здесь, а не тонет в движке. Строка допускается только если это реальное имя колонки фрейма.

## VIII.5. Диспетчер физики `_handle_apply_physics_formula`
Порядок: валидатор → `ey_coupling` → `_SOLAR_WIND_SCALAR_METRICS` (`burton_coupling`, `akasofu_epsilon`) → `_TWO_FRAME_METRICS` (`eej_index`) → `peak_dhdt`+`window_seconds` → `func(frame)`.

## VIII.6. Alias-таблицы (устойчивость к формулировкам модели)
- **`_PHYSICS_METRIC_ALIASES`**: `dh_dt`/`dh/dt`/`gic_proxy`→`gic`, `sq`→`sq_baseline`, `ssc`→`detect_ssc`, `dst`→`dst_proxy`, `ey`→`ey_coupling`, `burton`→`burton_coupling`, `akasofu`/`epsilon`→`akasofu_epsilon`, `peak_dh_dt`→`peak_dhdt`, `substorm`→`substorm_onset`, `eej`/`equatorial_electrojet`→`eej_index` и др.
- **`_SOLAR_WIND_HANDLE_KEYS`**: `solar_wind`, `solar_wind_handle`, `solar_wind_frame`, `sw`, `sw_handle` — указание на сохранённый фрейм ветра вместо чисел.
- **`_self_correction_hint`**: галлюцинация → конкретное действие (`calculate_dst_proxy` → «используй `apply_physics_formula(metric='dst_proxy')`»); при `unknown_frame` hint = актуальный `scratchpad.current_handle`.

## VIII.7. `FrameStore` — хэндлы
Хранит реальные DataFrame, чтобы они не ходили через JSON. Каждый фрейм — постоянный слот (`raw:irt:2024-09-10`). Семейства `raw`/`derived`/`anomalies` — алиасы на последний член семьи. `derive_name` сохраняет суффикс: `raw:irt:D` → `derived:irt:D`. `resolve` при промахе отдаёт `unknown_frame` со списком **реальных** доступных хэндлов и алиасов.

## VIII.8. Динамический выбор инструментов
Полный список из 29 схем переполняет окно 7B. `select_tools_for_query` берёт:
- всегда `fetch_observatory_data`;
- при массовых словах — матричную пару (`_MATRIX_TOOLS`);
- по `_QUERY_TOOL_KEYWORDS` — нужные инструменты (NOAA, SuperMAG/суббури, ISWA, Kyoto/индексы, «Земля vs космос», графики, статистика, аномалии, дельты/формулы, физика, EEJ, MLT/координаты, проекты);
- результат упорядочен, дедуплицирован, обрезан до `TOOLS_PER_TASK = 6`; матричная пара обязательна для массовой задачи.

## VIII.9. Бюджет промпта
- `len(SYSTEM_PROMPT) = 3199` символов (проверено).
- `estimate_tokens`: ~3 симв./токен кириллица, ~4 латиница.
- `prompt_budget(...)`: `est_tokens ≤ N_CTX//2 = 8192`.
- `N_CTX = 16384` (было 8192 — при полном списке схем оставалось ~200 свободных токенов → пустой ответ).
- `FRAME_SUMMARY_MAX_CHARS = 400`, `FALLBACK_HINT_MAX_CHARS = 800`, `TEMPERATURE = 0.1`, `MAX_TOKENS = 1200`, `MAX_BATCH_DOWNLOADS = 8`.

## VIII.10. Промпт: правила
`SYSTEM_PROMPT` (= `BASE_PROMPT_COMPACT`) содержит «ПРАВИЛО 0 (ДЕКОМПОЗИЦИЯ)» и нумерованные правила 1–11 + блоки «ГРАФИКИ (ЕСЛИ → ТО)», «КОСМИЧЕСКАЯ ПОГОДА», «ИНСТРУМЕНТЫ», «ФОРМАТ ОТВЕТА», «АЛГОРИТМ ДЛЯ МАССОВЫХ ЗАДАЧ». Ключевые запреты: не отвечать как `API-сервер` (`{'content':..., 'tool_calls':...}`); метрики `'range'` не существует; `calculate_dst_proxy` не существует; хэндлы строчными; числа — только из инструментов.

# ЧАСТЬ XI. УСТОЙЧИВОСТЬ И ЧЕСТНОСТЬ

**Graceful Degradation:**

| Отказ | Поведение |
|-------|-----------|
| Неизвестный инструмент | `unknown_tool` + список + подсказка |
| Невалидный JSON вызова | `malformed_tool_call` + образец |
| Исключение в хендлере | `tool_exception`, traceback в stderr, цикл жив |
| Исчерпан бюджет | каждая отказанная пара — строкой, принудительный ответ |
| Исчерпаны раунды | `stop_reason="round_limit"` + список падений |
| Ошибка движка | `{"ok":False, "error", "message", "missing", "available", "hint"}` |
| Сеть недоступна | `GEOMAG_OFFLINE=1` → синтетика; иначе ошибка+hint |
| График не восстановился | текст всё равно приходит, `_fallback_note` указывает файл |
| Станция в `fetch_many` упала | в `failed`, остальные работают |

**Принцип:** ничто не должно убить сервер; один плохой ход не роняет процесс.

**Offline-режим:** у каждого сетевого хендлера есть синтетический аналог (`_offline_frame`, `_offline_solar_wind` с южным Bz, `_offline_indices`, `_offline_noaa`, `_offline_iswa_forecast`, `_offline_supermag`). Тесты сети — под маркером `network`.

**Честные ограничения:**
- Definitive-данные экваториальных станций отстают на месяцы → `calculate_eej_index` несёт `CRITICAL FALLBACK` (повторить с `data_type='auto'` или историческим годом).
- ISWA WMS декомиссирован → `fetch_supermag_data(data_type='indices')`.
- Геомагнитные координаты — первый порядок (наклонный диполь), не IGRF.

**Credential isolation (SuperMAG):** логин вводится в поле `type="password"`, пишется в `os.environ["SUPERMAG_LOGON"]` **на время запроса** в `submit(...)`, в историю чата и журнал инструментов **не попадает**. Ограничение: живёт в процессе между запросами (для одиночного пользователя приемлемо).

# ЧАСТЬ XV. САМООБУЧЕНИЕ — ГДЕ ОНО НА САМОМ ДЕЛЕ

Важно честно: полного градиентного обучения в проекте нет. Есть **три механизма адаптации**, которые дают эффект обучения:

1. **Scratchpad + детектор цикла** — система помнит свои ошибки в рамках запроса, на 3-м одинаковом провале меняет стратегию (`[CRITICAL LOOP DETECTED]` + конкретный фикс). Это «обучение на своих ошибках» без весов.
2. **Самокоррекция (`_self_correction_hint`, alias-таблицы)** — галлюцинация имени/аргумента превращается в правильный вызов.
3. **Планировщик + `SessionState`** — знание о ходе большой задачи вынесено из окна модели в объекты, поэтому 7B выполняет работу, которая иначе не помещается в контекст.

Это осознанная инженерная позиция: **знание наружу, из окна — в Python.**
