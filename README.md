# Геомагнитный ИИ-агент

Исследовательский MVP: локальная Qwen 2.5 14B управляет Python-инструментами для загрузки геомагнитных рядов, расчётов, интерактивных графиков и архивирования результатов. Пользователь работает через Gradio на русском языке; таблицы остаются в Python, модель получает их идентификаторы и краткие результаты.

Простая полностью определённая статистика по загруженной таблице исполняется инструментом напрямую, без повторного выбора аргументов моделью. Это гибридное исполнение, а не заявление, что каждый вызов в проекте сформирован LLM.

Проект демонстрирует основу будущего SaaS. Авторизация пользователей, разделение файлов между организациями, биллинг, долговечная очередь заданий и эксплуатационные гарантии пока не реализованы.

**Длинный диалог ещё не принят полностью.** После исправления прямого исполнения статистики пользователь подтвердил отдельные запросы BOU X/Y/Z/H журналами инструментов; F — итоговым ответом. Единого повторного полного 20-ходового прогона на последнем коде пока нет. [Результат, решение и исследование графиков](docs/STATS_EXECUTION_20261103.md), [более ранний запуск](docs/LIVE_BEFF60B_20261103.md).

Подготовлена [программа глубокого QA: 22 направления](docs/QA_MASTER_PLAN.md), [реестр научных эталонов и известных вопросов](docs/QA_SCIENCE_LEDGER.md), [первичные карточки всех 29 инструментов](docs/qa/TOOL_RUNBOOK.md). Это план, а не отчёт о прохождении. Независимая проверка единиц выявила ошибку масштаба Ey; научная приёмка этой метрики не завершена.

После первого пользовательского запуска каталога подготовлены [разбор причин и исправлений](docs/QA_ROUND1_REVIEW.md), [готовые запросы с зависимостями](docs/qa/TOOL_RUNBOOK.md) и [отдельная линейка формул](docs/qa/FORMULA_RUNBOOK.md). Незаполненные поля вида `{PROJECT}` теперь вызывают уточнение; EEJ без обоснованной пары не считается проверенным.

## Возможности

- Суточные ряды обсерваторий: X/Y/Z/F, производные H/D/I, статистика, аномалии и арифметические выражения из ограниченного языка формул.
- Сравнение дней и станций, отдельные панели для разных единиц, сопоставление наземных рядов с OMNI.
- Задачи «станции × даты»: планировщик формирует матрицу, Python выполняет её и отмечает полные, частичные и пустые результаты.
- Проекты с CSV, JSON-метаданными и HTML; ZIP с индексом, сортировкой и пользовательской структурой папок. Компактный ZIP доступен через Python API.
- Память таблиц внутри браузерной сессии и короткий контекст предыдущих сообщений. Это не бесконечная и не долговременная память.

В каталоге модели — 29 инструментов, включая экспериментальные физические метрики. Их наличие не означает научной аттестации: известные ограничения вычислений перечислены в [разборе кода](docs/CODE_REVIEW.md).

| Источник | Поддерживается | Граница |
|---|---|---|
| INTERMAGNET / Edinburgh GIN | Каталог, X/Y/Z/F, состояния публикации, кэш; fallback через Kyoto | Подмножество служб; наличие станции не гарантирует данные за любую дату |
| NASA CDAWeb / OMNI | Два минутных OMNI-набора; V/Np/T/Bx/By/Bz | Не весь CDAWeb; временная привязка OMNI уже учитывает перенос к головной ударной волне |

| NOAA SWPC | Геомагнитные уведомления, прогноз Kp, семидневный каталог вспышек | Не исторический архив всех событий; название инструмента forecast не означает прогноз скорости ветра |
| SuperMAG | Клиент станционных возмущений, SME/SML/SMU и inventory | Старый адрес indices.php ответил HTTP 404 при проверке 01.11.2026; восстановление текущего API не выполнено |
| NASA ISWA | Выбранные Kp/Dst HAPI-продукты | Не вся ISWA; Dst здесь наблюдение, не прогноз. Legacy-карта в коде отключена с service_decommissioned |

Это **шесть специализированных интеграций**, а не полная реализация шести сайтов/API. Подробности и первичные источники: [SOURCE_COVERAGE.md](docs/SOURCE_COVERAGE.md).

## Что подтверждено

- Локальная проверка после ремонта диалога 03.11.2026: **1070 passed, 1 skipped, 22 deselected** в изолированной копии (verification/20261103T082558Z). Это офлайн-тесты; сеть исключена, реальная модель локально не загружалась. Включён replay двадцати ходов с рабочим selector и намеренно ошибочным итоговым текстом тестовой модели. [Сценарий живой приёмки](docs/LONG_CHAT.md).
- Настоящая HTTP-очередь Gradio 6.29.0: семь групп проверок, включая 14 сообщений, две независимые сессии, Plotly, HTML/ZIP-download и «Новый диалог» (verification/20261103T080717Z_gradio). Selector рабочий, модель и загрузчик — тестовые исполнители. Это не приёмка понимания настоящей Qwen.
- В браузере проверена отрисовка графика. Отправка многострочного вопроса в проверенной Gradio 6.29.0: кнопка **«Спросить»** или **Shift+Enter**.
- Сохранённый [вывод Kaggle stress_3ffd1r21 от 28.10.2026](docs/evidence/stress_3ffd1r21_cell10_output_redacted.log): **300/300 графиков**, `skipped: none`, `failures: none`, успешный security probe; SuperMAG вернул два окна по **21 600 строк**. Это исторический результат старого клиента, не подтверждение сегодняшней доступности SuperMAG.[^historical]

Актуальные проверки после исправлений, версии зависимостей и границы доказательств: [VALIDATION.md](docs/VALIDATION.md). В артефактах проверки сохраняются хеши файлов: номер Git-коммита при наличии незакоммиченных изменений недостаточен.

## Запуск

Python 3.12:

```bash
python -m pip install -r requirements.txt
```

Для настоящей модели отдельно установите `llama-cpp-python` подходящей CPU/CUDA-сборки; см. `requirements-llm.txt` и [инструкцию приёмки на Kaggle](docs/KAGGLE_ACCEPTANCE.md). Веса GGUF скачиваются при явной загрузке модели. Их объём и потребление памяти требуют подходящего оборудования.

```bash
python gradio_app.py
```

Gradio использует модель, загружаемую один раз на процесс. Публичная ссылка по умолчанию отключена; стандартный сервер слушает `0.0.0.0`. Для доступа только с этого компьютера задайте `GRADIO_SERVER_NAME=127.0.0.1`. `GRADIO_SHARE=1` включают только для осознанного показа: встроенной авторизации у приложения нет.

Пример первого вопроса:

> Станция IRT, 2024-09-10. Загрузи данные, вычисли H, D, I. Посчитай статистику H и построй H. Укажи источник и точный handle данных.

Продолжение в той же сессии:

> Теперь построй D из тех же данных. Повторно не скачивай их. Укажи использованный handle.

## Воспроизводимые проверки

На Kaggle код загружается прямо из GitHub: используйте [девять ячеек](docs/KAGGLE_ACCEPTANCE.md) в свежем kernel. Dataset/Input и ручная загрузка ZIP не нужны. Первая ячейка создаёт отдельный checkout, фиксирует HEAD/хеши и повторно использует прежние веса.

```bash
python -B tools/verify_offline.py
python -B tools/verify_gradio.py
python -B tools/probe_sources.py
python -B tools/verify_notebook.py
```

Первая команда тестирует отдельную временную копию исходников. Вторая проверяет реальный Gradio с явно обозначенными тестовыми данными. Третья проверяет только публичные адреса, без логина SuperMAG. Четвёртая проверяет логику notebook на локальных фикстурах и Git-репозитории. Отчёты — в `verification/`. Ни одна из этих команд не заменяет живую проверку Qwen на GPU.
